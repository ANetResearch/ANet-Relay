# ANet Relay v0.5.1 设计：Copilot 运行轨迹、自定义对抗与横幅

状态：约束性契约（v0.5.1）。基线：v0.5.0（`docs/design/07-v050.zh-CN.md`）。

## 0. 负责人要求

1. 配置 DeepSeek 后输入复杂指令，对话里看不出 Copilot 是否在运行，除工具进度外看不到任何过程。要一个小小的红色像素飞机，运行时可点开下钻查看思考过程、调用情况和模型反馈。
2. 指令“创建三架虚拟飞机，A 尽量飞 8 字并优先躲避、可获取全局状态；另两架只有视角，一架撞毁 A，一架用子弹打掉 A”只是偶尔成功，需稳定可用。
3. README 横幅改为更扁、带 ANet 标志与 ANet Relay 名称的动图，首帧与尾帧相同，风格沿用 `brand/social-preview@2x.jpg`。
4. 版本 0.5.1。

## 1. 根因（以 DeepSeek V4.1 Flash 实测）

- Copilot 把模型声明为非推理模型（`reasoning: false`），`maxTokens` 为 4096。DeepSeek V4 系列默认开启思考，思考与回答共用输出上限，复杂指令下整轮输出被思考耗尽，结束原因为 `length`，既无文字也无工具调用。
- 渲染端遇到无文字、无错误的回合直接删除，界面上表现为“什么都没发生”。
- 主进程只转发文字增量与工具开始/结束，思考增量、工具参数撰写、每轮用量与结束原因全部丢失；工具结果截断到 600 字符。
- 场景本身缺少表达手段：手动部署无法设定队伍（接触对象的 `team` 默认是自身 id，两架攻击机可能互相追逐），开火需要竞技场开启，而 `dogfight_start` 只支持 gunner / rammer 两种角色、统一的传感器。

## 2. 模型设置

`copilot.json` 新增两项，在 设置 → Copilot 中编辑：

| 字段 | 取值 | 默认 | 作用 |
|---|---|---|---|
| `thinking` | `auto` / `off` / `low` / `high` | `auto` | `auto`：沿用服务端默认，不发送思考参数；`off`：声明为推理模型并关闭思考（DeepSeek 发送 `thinking: disabled`）；`low` / `high`：开启并发送对应强度 |
| `maxTokens` | 1024–131072 | 16384 | 单轮输出上限（含思考） |

任何取值下，服务端返回的思考内容（`reasoning_content` 等）都进入运行轨迹。

## 3. 运行轨迹事件（主进程 → Copilot 窗口）

每次提问是一个 **run**，由若干 **回合**（一次模型调用）和 **工具执行** 组成。在 v0.5 事件之外新增或扩展：

| 事件 | 字段 |
|---|---|
| `run_start` | `run`, `at`, `model`, `thinking` |
| `turn_start` | `run`, `turn`, `at`（与 `assistant_start` 同时发出） |
| `thinking` | `turn`, `delta`（每 120 ms 合并一次） |
| `draft` | `turn`, `tool`, `chars`（模型正在撰写工具参数，每 250 ms 一次） |
| `assistant_end` | 增加 `turn`, `stopReason`, `usage {input, output, reasoning, cacheRead, total}`, `ms`, `toolCalls [{id, name, args}]`（参数 JSON 截断至 12000 字符） |
| `tool_start` | 增加 `turn`, `at` |
| `tool_end` | 增加 `ms`, `full`（结果截断至 12000 字符；`text` 仍为 600 字符摘要） |
| `run_end` | `run`, `at`, `ms`, `turns`, `tools`, `usage`, `outcome`（`done` / `error` / `aborted` / `empty` / `length`） |

回合以 `length` 结束、或无文字无工具调用时，窗口保留该回合并给出说明：`length` 提示调高最大输出或降低思考强度；空回合提示模型未给出回复。

## 4. 像素飞机与下钻

- 每条用户消息下方是该次运行的 **运行条**：7×7 像素的俯视四旋翼（四角 2×2 旋翼、中心 3×3 机身），红色（`--r500`），旁边是阶段与计时。运行中旋翼以 `steps()` 交替闪烁、机身上下 1 px 起伏；结束后静止。减弱动效时始终静止。
- 阶段：等待模型 → 思考中（已思考字数）→ 回复中 → 准备调用 {工具}（参数字数）→ {工具} 执行中 → 等待批准 → 完成 / 出错 / 已停止。
- 运行中，输入框上方固定一条同样的运行条（替代 v0.5 的“思考中”文字），点击即展开当前运行。
- 点击运行条展开 **轨迹**：每个回合一行（序号、耗时、输入 / 输出 / 思考 tokens、结束原因），每个工具一行（名称、飞机、耗时、结果）；行可展开查看思考全文、模型回复、工具参数 JSON、工具结果全文。底部合计回合数、工具数、tokens 与总耗时。
- 红色是负责人明确要求的例外，仅用于像素飞机本身；轨迹面板沿用灰阶。

## 5. 自定义对抗

- `POST /scenarios/dogfight` 新增 `entrants`（2–8 项，给出时以其长度为飞机数，忽略 `aircraft` / `roles` / `teams`）。每项：`role`（`gunner` / `rammer` / `pilot`；`pilot` 不开火）、`program`（`pilot` 必填，其余默认同角色）、`team`（≤16 字符，默认自身 id）、`position`（`none` / `uwb` / `gps`，默认 `none`）、`params`（程序参数）、`label`（≤16 字符，可选）。程序声明了 `team` 参数时自动填入所在队伍。视图 `config.entrants` 与 `aircraft[*].team / position` 反映实际设置。
- `POST /vehicles/{id}/program` 新增 `team`：设定该飞机在接触表中的队伍，并填入声明了 `team` 参数的程序。
- 新内置示例 `figure8_evader`：依靠位置源绕场地中心飞 8 字（Gerono 双纽线，速度前馈 + 位置修正，30° 摇杆映射），高度按气压计保持并缓慢起伏；当另一队的接触在 `threat_dist` 内以超过 `threat_closing` 的速度逼近时，横向闪避（偏向场地中心）并改变高度，从不开火。
- Copilot 工具 `dogfight_start` 接受 `entrants`，系统提示给出映射：“A 飞 8 字并躲避、可获取全局状态，一架撞 A、一架打 A” → `dogfight_start {entrants: [{role: "pilot", program: "figure8_evader", team: "A", position: "gps", label: "A"}, {role: "rammer", team: "B"}, {role: "gunner", team: "B"}]}`。
