# 13 · v0.6.1：时间轴工作区

本文是 0.6.1 的实现约定。它替换 `10-v053` §2.3（舞台下方的时间轴面板）；`.ars` 文档、后端路由和执行规则
（`10-v053` §2.1、§2.2）不变。

## 1. 为什么改

- 面板停靠在飞行工作区的舞台下方，两侧面板展开时轨道只有约 350 px 宽，19 秒的序列只能看到 7 秒；时间轴
  每秒固定 48 px，不随窗口伸缩。
- 调参是“改一个数 → 执行 → 看 → 停 → 再改”的循环，原流程要选飞机、进控制页、附身、向下滚动、打开面板、
  执行、输入 ARM，七步。
- 方向键只能微调，不能在块之间移动；只能单选；按键说明是一段灰字。
- 不能用文本写序列。

## 2. 工作区

顶栏第五个标签“时间轴 / Timeline”（内部 id `sequence`；`timeline*` 在 `store/ui.ts` 里已经指底部的控制权时间线）。
按 `5` 进入，任何位置（含编辑器）按 `Alt+5`。

自上而下：

| 沙盘 + 监视 | 缺省 260，可拖 160 到半屏，可收起 | 沙盘（`<Stage bare />`，只留视角工具）；光标处两个摇杆（可拖）、实时数据（高度、垂直速度、姿态、电池、模式）、四个微调 |
| 执行栏 | 44 | 目标飞机、控制者、执行、从光标处执行、停止、速度 0.5×/1×/2×、先复位、状态、实时/已同步、恢复上次序列、录制；底边是进度线 |

窗口宽度不足 1200 px 时没有分屏。

### 2.1 时间轴的宽度

- “适应宽度”是状态而不是一次性操作：`每秒像素 = (视口宽 − 24) / 总时长`，窗口缩放、打开分屏、时长变化都会重算；
  此时没有横向滚动条。
- `Ctrl/⌘` + 滚轮（以指针为中心）或 `Alt+=` 放大后离开适应状态，`\` 回到适应；不能缩小到小于适应宽度。放大后
  滚轮横向滚动，飞行中播放头到视口 85% 处翻页。`Z` 缩放到所选块。
- 标尺刻度取 0.1、0.5、1、2、5、10、30、60 秒中标签间距不小于 56 px 的最小值。
- 轨道高度随可用高度伸展：`clamp(40, (高度 − 34 − 22 − 48) / 4, 88)`。

### 2.2 选择与编辑

- 选择是一组块加一个主块（最后点到的那个，粗描边）。点击单选；`Ctrl/⌘`+点击增减；`Shift`+点击从主块选到
  该块（跨轨道时取中间各轨道与时间范围重叠的块）。点标尺或摇杆条只移动光标。
- 上下拖动：所有选中块的杆量同增同减（0.01 一格，`Shift` 精调 ×0.2）；拖右边缘改时长；拖左边缘只移动起点；
  双击切分。
- **联动**（缺省开，`G`）：某条轨道上改时长、插入、复制时，其他三条轨道上位于该边界之后的键一起移动
  （`model.ts::rippleFrom`，不会越过各自的前一个键）。关闭后是 0.5.3 的单轨道行为。
- 撤销、重做保留仍然存在的选中块。

### 2.3 按键

目标飞机。`Alt+1`…`Alt+5` 在任何位置切换工作区。

## 3. 代码视图

同一个文档的另一种写法：**时间表**。每个有杆量变化的时刻一行，每个摇杆轴一列；一行就是时间轴上的一条竖线，
一格就是一个操作块。

```
name  起飞-悬停-降落
mode  althold
trim  pitch -0.04  roll 0  yaw 0  throttle 0

time | throttle     | pitch  | roll | yaw
0    | 0.50 spool   |  0.00  |      |
+0.5 | 0.75 climb   |        |      |
+2.5 | 0.50 hover   |        |      |
+1   |              | -0.08~ |      |
+2   |              |  0.00  |      |
+2   | 0.30 descend |        |      |
+9   | 0.00 settle  |        |      |
+2   | end disarm
```

- 时间：`+0.5` 表示距上一行 0.5 秒（缺省写法：把某一段加长 0.3 秒只改一个数，后面所有轨道随之后移）；也可写
  绝对秒数，逐行混用。行号位置显示该行的绝对时间（切到“绝对时间”写法时显示间隔）。
- 格：`杆量[~][ 名称]`，`~` 表示渐变到本轨道的下一个键；空格表示这一时刻该轨道没有键；整列为空表示文件里没有
  这条轨道。名称里的 `|`、`#` 写作 `\|`、`\#`。
- 表头三行 `name`、`mode`、`trim`；最后一行 `<时间> | end disarm|hold` 给出总时长和结束方式。整行注释以 `#` 开头，
  保存在 `source.comments`（后端原样保留 `source`）。
- 对齐：离开编辑器、保存、执行、点“对齐”时格式化（竖线对齐，列宽取最宽的格，方向轴带符号位）。不会在数字
  打到一半时改动文本。
- 往返：`parseCode(toCode(doc))` 与 `doc` 完全相等（`sequence/code.test.ts` 对全部模板和文档示例验证）。
- 报错：停止输入 150 ms 后解析，问题标在编辑器里并显示第一条，例如“第 7 行：油门：杆量须在 0 到 1 之间”。
  有问题时轨道显示上一次有效内容（变暗、只读），执行按钮禁用：打到一半的文本不会上天。
- 编辑器按键：`Alt+↑/↓` 微调光标处的数字（杆量 ±0.01，时间 ±0.1 秒；`Shift` ×5）；`Tab` / `Shift+Tab` 下一格、
  上一格。
- 同步：代码里每次有效解析都替换文档（一段连续输入算一步撤销）；轨道上的每次编辑（含拖动中的每一帧）只改写
  文本里变化的部分。光标所在的格选中对应的块，时间轴光标移到该行；选中的块在文本里高亮。执行时正在飞的那一行
  有标记，已飞过的行变暗。

实现：`sequence/code.ts`（`toCode`、`parseCode`、`nudgeNumber`）、`sequence/SequenceCode.tsx`（实验室同一套
CodeMirror 与主题）。

## 4. 执行

- 目标飞机就是全局选中的飞机（执行栏左侧可换）；没有飞机时执行栏只有“添加模拟机”。
- 执行时自动做掉安全的前置步骤：空闲的模拟机自动附身；未解锁或已坠毁的模拟机先复位到出生点（“先复位”开关，
  缺省开，固件孪生除外）；`speed` 按所选倍速发送。
- 需要人决定的在执行栏内询问，不弹出、不挤走其他内容：真机在地面执行要输入 `ARM`（每次都要，规则与
  `02` §11 一致）；真机未附身要先点“附身”；飞机在智能体手里要确认“接管并执行”。
- 飞行中每次提交的编辑和每次有效解析都经 `PATCH /sequence` 发给飞机（轨道 80 ms、代码 300 ms 去抖），执行栏
  显示“已同步”。
- 响应轨：执行期间按序列时间记录高度，下一次执行时上一条变成虚线，标签显示两次的峰值。执行栏的“恢复上次执行的
  序列”把文档换回上一次飞过的版本（可撤销）。

## 5. 文件与持久化

- 始终有一个文档；第一次进入是起飞模板。
- 序列库（按观看者保存在本机，最多 50 个）：`Ctrl/⌘+S` 以当前名称保存，同名覆盖。打开菜单列出序列库、四个
  模板（起飞悬停降落、油门阶跃、俯仰横滚双脉冲、空白 10 秒）和导入、导出；把 `.ars` 文件拖到工作区即导入。
- `localStorage`：`relay.sequence.doc`（工作副本）、`relay.sequence.library`、`relay.sequence.view`（视图、联动、
  倍速、先复位、时间写法、适应或缩放、沙盘高度、分屏比例）。

## 6. 同一版本的其他改动

- 底部的控制权时间线按工作区记忆折叠状态：飞行、智能体缺省展开，记录、实验室、时间轴缺省只留标题行。
- 命名：控制页的分步计划叫“动作计划 / Action plan”，摇杆编辑器叫“时间轴 / Timeline”，底部条仍叫“控制权时间线”。
- 后端：时间轴在切换模式和解锁阶段（键盘附身时再加执行开始后的 1 秒）重新记录操作员的静止杆位。键盘的静止
  油门随飞行模式变化（自稳在底部，定高在中位），原来会被误判为“操作员接管”而中止序列。
- 应用控制（`app_set_workspace`、Copilot 的 `set_workspace`）接受 `sequence`。

## 7. 没有做的

- 真机的“执行许可”（输入一次 ARM 后一段时间内长按即可执行）：它放宽 `02` §11 的规则，需要产品负责人决定。
- 复制、粘贴操作块，磁性吸附，按键表由全局快捷键注册表生成。
- 控制页分组折叠、命令面板排序、沙盘叠层整理等其余体验项，见 UX 审查清单。

## 9. ANetDU7 室外方形航线（并入真机脚本的新版）

真机上实际飞过的测试节点有了室外版本 `vehicles/anet-du7/tests/u7_mavros_square10.py`：起飞 10 m，
前、左、后、右各 10 m，降落。它和 0.6.0 并入的 `u7_mavros_simple.py`（2 m、1 m）相比，飞法改了三处，
Relay 的限速跟踪（12 §4）照改：

| | 0.6.0 | 0.6.1 |
|---|---|---|
| 期望速度 | 0.8 × 位置误差，三维合速度限 `speed` | 水平：min(0.8 × 距离, `speed`, √(2 × 0.5 × 距离))；垂直：0.8 × 高度误差，限 0.5 m/s |
| 到位 | 连续 `settle_s` 秒留在 0.2 m 内 | 首次进入 0.2 m 起计时 `settle_s` 秒；到达时限用完也开始计时 |
| 步骤超时 | 按合速度估算 | 按水平、垂直两个限速估算；到达时限 = 该估算 + 8 s |

- 刹车曲线是限速提高后必需的：指令加速度限 0.5 m/s²，2.5 m/s 需要 6.25 m 才停得下来，而 0.8 增益在
  3.1 m 才开始减速。
- 垂直限 0.5 m/s 不随 `speed` 提高（真机脚本如此）。以前给 `takeoff` 传大于 0.5 的 `speed` 会爬得更快，现在不会。
- 到位不再要求“安静的 2 秒”：室外有风时飞机会在容差边缘进出，旧规则可能一直等到超时失败。
  靠到达时限结束的步骤仍算完成，`skill.detail` 写 `approach limit reached 0.43 m from the target`。
- 内置计划 `du7_square10`（`GET /plans/builtin`）：`takeoff 10`、`move forward 10`、`move left 10`、
  `move forward -10`、`move left -10`、`land`，`speed` 均为 2.5。计划步骤里 `forward` / `right` / `left`
  和 `move` 的 `x` / `y` 上限从 5 m 提到 30 m（安全区仍然约束实际能飞多远）。
- 没有照搬的：脚本的 30 m 半径、12 m 高度包线在 Relay 里就是安全区，缺省 3 × 3 × 2 m，飞这条航线前
  要先调大；脚本的角点是相对起飞点的绝对坐标，Relay 的 `move` 相对每一步开始时的位置，误差会逐步累加
  （模拟机上四个角均在 0.5 m 内）；垂直速度超限即停没有做，Relay 的超速监视仍是合速度超过限速
  0.5 m/s 持续 1 s。
