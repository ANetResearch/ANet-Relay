# ANet Relay v0.5.0 设计契约：真实物理、碰撞与多机狗斗

本文是 v0.5.0 的约束性契约，补充 01–06；与之冲突处以本文为准。接口位于 `/api/v1`，错误体沿用 03 §10，色彩、动效、图标、组件、文案纪律沿用 05 §0 与 06 §11（红色武器语义例外扩展到碰撞与爆炸，见 §5）。

## 0. 所有者的要求（2026-11-08）

1. 通过 Copilot 一句话启动多机狗斗场景：有的飞机开火，有的直接撞；要看到明显的子弹轨迹、高亮红色特效、碰撞体积和体素爆炸。子弹落地消失即可。
2. 穿环要有物理体积：环是实体，撞上会弹开或坠毁。
3. 整套物理更真实合理，参考 Gazebo。
4. 局域网加入后大家互相看到彼此的飞机；可以配置智能体接入，让飞机追逐、狗斗；有排行榜：存活最久、击落最多等。
5. 仍然只用摇杆（06 §5）：程序、智能体只能输出摇杆量与开关，不提供"去撞某架飞机""飞到某点"之类的高层接口。

## 1. 物理模型 v2（参考 Gazebo `MulticopterMotorModel`）

**现状。** v0.4 的 `sim/physics.py` 是质点模型：一个合推力，姿态以一阶滞后直接跟随目标角度，没有转动惯量、没有单个电机、没有转子阻力。机体缺陷（06 §4）以姿态偏置近似。

**改为六自由度刚体 + 四个转子：**

- 刚体：质量 `MASS`（缺省 0.12 kg，机体缺陷的载荷照旧叠加），对角惯量张量（缺省 Ixx = Iyy = 1.2e-4、Izz = 2.2e-4 kg·m²，按 25 cm 轴距、0.12 kg 估算并写明出处），四元数姿态，机体系角速度，欧拉方程 `I·ω̇ = τ − ω × (I·ω)`，250 Hz 半隐式积分，每步归一化四元数。
- 转子（X 型，编号与方向同 PX4 quad-x：1 右前 CCW、2 左后 CCW、3 左前 CW、4 右后 CW，与现有电机测试编号一致）：
  - 转速一阶动态，升速/降速时间常数不同（`τ_up` 0.0125 s、`τ_down` 0.025 s，同 Gazebo 缺省量级）；
  - 推力 `F = k_f · ω²`，反扭矩 `M = k_m · F`（方向随旋向），`k_f`、`ω_max` 由推重比 2.4 与悬停油门约 0.50 反推；
  - 转子阻力（Gazebo `rotorDragCoefficient`）：与转速和机体系侧向来流成正比的水平力；滚转力矩系数（`rollingMomentCoefficient`）；
  - 电池电压影响 `ω_max`（沿用 v0.4 的放电曲线与内阻）；
  - 地面效应、下洗涡环、阵风（OU 过程）照旧，作用到每个转子或合力上。
- 机体气动阻力：线性 + 二次阻力，按机体系各轴不同系数（迎风面积不同），保持 30° 倾角时最高速约 7 m/s 的手感（±15 %）。
- 机体缺陷（06 §4）改为物理来源：重心偏移是推力作用点相对质心的偏移，产生真实力矩；电机增益偏差是单个转子的 `k_f` 偏差；水平误差留在传感器估计里；桨损是单个转子的推力损失与振动。06 §4 的可观测行为（粗糙机体不加修正时 20 s 漂移 > 0.8 m、载荷下 0.5 油门起不来、同种子同轨迹）继续作为验收测试。
- **模拟飞控**（`sim/autopilot.py`）不再直接设姿态：
  - 角度环（P）→ 角速度环（PID，带 D 项低通与积分限幅）→ 混控器（含饱和时保持姿态优先的去饱和，类似 PX4 airmode 关闭时的行为）→ 四个电机油门；
  - STABILIZE/STABILIZED 的摇杆映射照旧（最大倾角 35°、偏航角速度 120°/s）；
  - ALT_HOLD、POSHOLD、GUIDED 等外环照旧，叠加在新内环之上；
  - 参数（各环增益）在模拟飞控内部，不暴露给会话（`sticks` 等级照旧）。
- 悬停辅助（05 §5）语义不变：开启时关闭缺陷、阵风等扰动，外环帮忙稳高稳位；关闭时一切物理效应生效。两种情况下都用同一个六自由度模型。
- 确定性：同种子、同输入、同步长得到逐位相同的轨迹（评测器依赖）。
- 性能：单机每个物理步不超过 v0.4.1 的 1.6 倍耗时；评测器 4 机对抗不低于 v0.4.1 的 80 %。实现可预计算常量、避免逐步分配。
- 交叉核对：`backend/tests/test_physics_gazebo.py` 以 Gazebo `MulticopterMotorModel` 的公式（不运行 Gazebo）独立实现一个参考转子，比较单转子阶跃响应、推力、反扭矩、转子阻力，误差 < 1 %；另测悬停油门、最大爬升率、最大平飞速度、偏航响应落在合理范围。

## 2. 碰撞体积与碰撞规则

新模块 `backend/relay/sim/collide.py`（纯函数，无 I/O），所有碰撞判定都用它；实时飞行、局域网场地、评测器共用。

**体积：**

| 物体 | 体积 |
|---|---|
| 飞机 | 球，半径 `CRAFT_RADIUS` = 0.15 m（25 cm 轴距加桨盘）；子弹命中球仍为 0.12 m（05 §7.4，不变） |
| 地面 | z = 0 平面（沿用 `_touchdown` 的坠毁阈值） |
| 圆环 | 圆环体（torus）：主半径 = 环的 `r`，管半径 `RING_TUBE` = 0.03 m；环的姿态由 `c` 与 `yaw_deg` 决定 |
| 场地边界 | 仅评测与狗斗场景：竖直圆柱（半径）与天花板；越界照旧判出局，不做物理墙 |

**检测：** 在 250 Hz 物理步上做扫掠检测（上一步到这一步的线段对球/圆环体），不会因速度快而穿透。

**响应：**

- 飞机对飞机：相对法向速度 `v_rel` ≥ `RAM_CRASH_V` = 2.0 m/s 时两机都坠毁（`crash_reason = "collision"`，电机停转、坠落）；小于此值时按恢复系数 0.4 的冲量弹开，并按接触点偏离质心产生角冲量（姿态被打乱，可救回）。
- 飞机对圆环：同样阈值。高速撞环坠毁，低速擦环弹开并扰动姿态；穿环判定照旧（03 §8），只有球心穿过环面且整个球不碰管体才计为干净通过；擦到管体通过仍计通过但记一次 `ring_touch`。
- 飞机对地面：沿用 v0.4 阈值，坠毁原因写入 `crash_reason`。
- 子弹落地：消失，无特效（所有者认可）。子弹不与圆环、飞机机体以外的物体碰撞。
- 被击落（HP 归零）的飞机在下坠过程中仍有碰撞体积，可以砸到别的飞机。
- 碰撞冲量通过 `Quad` 的新方法 `collide(normal, j, point)` 施加，`impulse()` 保留给子弹。

**事件（新增，双语文案）：** `collision`（data：`a`、`b`（飞机 id、远端键或 `ring:<i>`）、`point`、`v_rel`、`crashed: [ids]`）、`ring_touch`。坠毁沿用 `crashed` 告警，原因含"与 X 相撞"。

**观测（06 §2.2 扩展）：** `obs.collision`：最近 1 s 内的碰撞 `{t_ago, with, v_rel, normal}` 或 null；`obs.contacts[*]` 增加 `dist` 已有则保持，增加 `closing`（接近速度，m/s）。程序因此可以写"撞上后进入恢复状态"。

**局域网：** 每个终端只裁决自己的飞机（同 05 §7.3 子弹的做法）：用远端飞机的最新状态（含 0.15 s 前推）作为移动的球与本机做扫掠检测，碰撞只作用于本机飞机，并发送 `COLLIDE` 包告知对方；对方收到后用自己的状态复核（双方距离 < 2 × 半径 + 0.3 m 且时间差 < 0.3 s）再对自己的飞机施加同样的规则，避免一方单方面宣布。远端发来的 `COLLIDE` 受速率与年龄限制（同 `MAX_SHOT_AGE_S`）。

## 3. 狗斗场景（Copilot 一句话启动）

新模块 `backend/relay/scenarios.py` 与路由 `POST /scenarios/dogfight`、`DELETE /scenarios/dogfight`、`GET /scenarios/dogfight`。

**请求：**

```json
{
  "aircraft": 6,                      // 2–12 架模拟机
  "teams": "ffa" | 2 | 3,             // 混战或分队
  "roles": {"gunner": 4, "rammer": 2},// 角色数之和 = aircraft；缺省按 2:1 分配
  "programs": {"gunner": "hunter_medium", "rammer": "rammer"},  // 程序 id 或内置示例
  "arena": {"radius": 8, "ceiling": 4},
  "airframe": "typical",              // 06 §4 预设
  "hover_assist": false,
  "duration_s": 180,                  // 30–1800；到时自动结束
  "respawn": true,                    // 击落/坠毁后 5 s 原地复活（同 05 §7.4）
  "seed": 7
}
```

**行为：**

- 生成或复用模拟机（不足则 `add_sims`），在场地边缘等距分布出生点，朝向中心；设置机体与悬停辅助；
- 开启场地（未加入局域网时以本地练习模式运行：`Arena.network = false`，不监听端口；已加入局域网则就地加入当前对局）；
- 按角色部署程序（06 §2），解锁、起飞由程序自己完成（程序只用摇杆）；
- 计时、结束时停止程序、各机降落或停桨、给出排行榜；
- 真机永不参与（05 §7 第 3 条），请求中出现真机 id 返回 400；
- 控制权：场景占用这些模拟机（控制者为各自的程序）；人可以随时接管任何一架（`relay_handback` 语义照旧）。

**新增内置示例程序** `rammer`（只用摇杆）：找最近敌机，按比例导引（PN）追击，接近时加速对撞；撞后进入恢复状态（检测 `obs.collision`），稳住姿态再寻找下一个目标。`hunter_*` 增加简单的规避（被瞄准时侧滑）。两者都有单元测试，并在评测器里对抗通过冒烟测试（不要求胜率）。

**新增题目** `ram_easy`：击落（撞毁）一架悬停靶机，不得开火。

**Copilot / MCP / SDK：** 新工具 `dogfight_start`（参数同上）、`dogfight_stop`、`dogfight_status`、`leaderboard`；`app` MCP 与 Copilot 同名同参；SDK 增加对应方法。Copilot 提示里写明典型说法（"开一场 6 机混战，4 架开火 2 架撞击"）对应的调用。启动场景属于应用操作权限（04 §3：操作员，或开启 `agents_app_control` 的会话）。

## 4. 排行榜与局域网对局

**统计（每架飞机一行，键为 `callsign / SIM-n`，本机为 `SIM-n`）：** 控制者（程序名与版本、智能体会话名、人）、击落数、命中数、开火数、命中率、撞毁数（因碰撞使对方坠毁）、被击落数、坠毁数、当前存活时长、最长存活时长、造成伤害。

**对局（match）：** 狗斗场景开始即开一局；局域网中任意终端可以 `POST /arena/match`（`{duration_s}`）发起一局，各终端收到 `MATCH` 包后清零本局统计，同步开始与结束时刻（以发起者的时间为准，带容差）。不在对局中时统计持续累积，`DELETE /arena/match` 重置。

**榜单：** `GET /arena/leaderboard?by=downs|survival|accuracy|rams` 返回合并后的全局榜单：本机统计 + 各对端在 `STATE` 中每 1 s 附带的本机统计摘要（新的可选字段，旧版本对端没有此字段时只显示其飞机，统计栏为空）。击落与撞毁的归属：命中由目标所在终端裁决（05 §7.3），通过 `HIT`（已有）与 `COLLIDE`（新增）回报给射手/撞击者所在终端计数。

**协议：** wire 版本号 +1；新包 `COLLIDE`、`MATCH`；`STATE` 增加可选统计块。与 v0.4 对端互通：互相可见、子弹可互相命中；碰撞与排行榜只在双方都是 v0.5 时生效。所有新包受与 `SHOT`/`HIT` 相同的大小、速率、年龄与来源校验。

**智能体接入：** 局域网里其他人的智能体通过各自终端的 `sticks` 等级会话驾驶各自的模拟机，或部署程序；本终端看到的只是远端飞机的状态，与控制者无关。排行榜显示控制者名称（由各终端在统计块中提供，最多 32 字符，按纯文本处理）。

## 5. 视觉

**共享模块 `web/src/arena/voxelFx.ts` 扩展：**

- `explosion`（击落、撞毁、高速坠地）：
  - 0–120 ms：白热核心方块迅速膨胀；
  - 随后 60 块体素沿球面向外炸开，颜色从白 → `r400` → `r600` → `g500` 随时间冷却，受重力与阻力，落地后停在地面渐隐；
  - 一圈贴地扩散的灰色体素尘环（离地低于 1 m 时）；
  - 总时长 `--duration-arena-explosion`（1200 ms）。
- `collision`（机间碰撞、撞环，不致坠毁的轻碰）：接触点一簇白红火花体素（16 块）与一个短暂的白色冲击方块，时长 `--duration-arena-burst`。
- 坠地（非碰撞、非击落的普通坠毁）：尘环 + 少量灰色碎块。
- 子弹（06 §11）：弹道加长到 `--duration-arena-trail` = 120 ms，弹头光晕加大；本机/他方区分保持。子弹落地直接消失。
- 镜头震动：本机跟随视角下，距离 5 m 内的爆炸或碰撞让相机做一次衰减抖动（幅度随距离衰减，最大 3 cm、120 ms）；reduced-motion 下关闭。
- reduced-motion：所有爆炸与碰撞退化为静止的白色方块标记，持续时长同上。

**碰撞体积可视化：**

- 圆环按真实管半径渲染成实体（体素化的圆环管，`g300` 主体，下一个目标环 `white` 描边），被擦到时闪一下白色；
- 图层开关"Collision volumes / 碰撞体积"（缺省关闭）：打开后每架飞机显示半透明的碰撞球线框（`g500`），子弹命中球与之区分（虚线）。

**排行榜界面：** Fly 工作区场地开启时，右上角一个可折叠的 `Leaderboard / 排行榜` 面板（shadcn Card + Table，lieflat 规则）：标签页 `Downs / 击落`、`Survival / 存活`、`Accuracy / 命中率`、`Rams / 撞毁`；每行：名次、飞机、控制者、主指标、次要指标；本机飞机行加粗；对局倒计时。场景运行中显示"结束对局"按钮。

**Lab 回放（06 §3.4）：** 轨迹增加 `collision`、`crash` 事件；回放画面同样显示爆炸、碰撞火花、尘环，拖动可定格。

**启动入口：** 除 Copilot 外，Fly 工作区顶栏 `Arena` 菜单新增 `Start dogfight… / 开始狗斗…`，弹出 shadcn Dialog 填写 §3 的参数。
