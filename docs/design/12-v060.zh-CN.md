## 1. 结论

1. **机型**：`vehicle.model` 取 `anet-du7` 或 `micro`。新建模拟机默认 ANetDU7（物理机型预设 `anet-du7`，
   PX4 风格）；`micro-120` / `small-250` / `large-450` 仍可选。真机默认按 ANetDU7 显示，可逐机改。
2. **坐标体系**：设置项 `control_frame`（`flu` 默认，或 `frd`），每个请求可用 `frame` 覆盖。
3. **云台**：`vehicle.gimbal`。ANetDU7 模拟机自带模拟吊舱；真机通过 TCP 2000（或串口）挂接 DYT 吊舱。
   `POST /vehicles/{id}/gimbal` 一套动作同时适用于两者。
4. **真机流程**：与 `u7_mavros_simple.py` 等价的机体系速度跟踪（位置误差 P 控制、限速、限加速度、到位保持）
   成为 ANetDU7 的默认飞法。

## 2. 机型 ANetDU7

来源：海报技术参数。四旋翼，轴距 500 mm，含保护架 684 × 684 × 211 mm，起飞重量 2.50 kg（含电池、保护框），
4S 5300 mAh 45C，续航约 10 min；飞控 CUAV X7+（PX4 稳定版），机载电脑 Jetson Orin Nano Super，
激光雷达 Livox MID360S，可选深度相机、光流。

### 2.1 物理预设 `anet-du7`（`sim/frame.py`）

| 字段 | 值 | 依据 |
|---|---|---|
| mass_kg | 2.5 | 海报 |
| wheelbase_m | 0.50 | 海报 |
| prop_in | 10 | 500 mm 轴距常用 10 寸桨（照片比例） |
| thrust_to_weight | 2.0 | 10 min 续航、2.5 kg 的载重机 |
| cells / capacity_mah | 4 / 5300 | 海报 |
| omega_max | 1000 rad/s | 10 寸桨约 9500 rpm |
| tau_up_s / tau_down_s | 0.04 / 0.06 | 大桨 |
| load_current_a | 62 | 悬停油门约 0.58 时约 27 A（5.3 Ah × 0.85 / 10 min；电池模型为 load × throttle^1.5） |
| r_internal_ohm | 0.012 | 4S 45C |

惯量按 `inertia_from`，机体阻力按 `_preset`，另乘 1.6（保护架迎风面积）。

### 2.2 `vehicle.model`

- 类型 `Literal["anet-du7", "micro"]`。模拟机：物理预设为 `anet-du7` 时是 `anet-du7`，否则 `micro`。
- 真机：默认取设置 `real_model_default`（默认 `anet-du7`）；`POST /vehicles/{id}/model {model}`（操作员）逐机修改，
  按机身标识持久化。
- `POST /sims`：`frame` 缺省时取设置 `sim_frame_default`（默认 `anet-du7`）。`frame.preset == "anet-du7"` 且未给
  `autopilot` 时用 PX4 风格。对战（dogfight / match）、评测（judge）、内置程序始终显式使用 `micro-120`，行为不变。
- 模型尺寸表（`GET /capabilities` 的 `models`，舞台用）：

| model | span_m（含保护架外廓） | height_m | 说明 |
|---|---|---|---|
| anet-du7 | 0.684 | 0.211 | 自带云台吊舱 |
| micro | 0.166 | 0.045 | GoFilm 20 |

- 模拟机出生点格距 2 m 不变（ANetDU7 外廓 0.684 m）。

## 3. 坐标体系

内部规范不变：本地 ENU（x 东、y 北、z 上，米），姿态 roll 右倾正、pitch 抬头正、yaw 为 NED 航向（北 0，顺时针正，弧度）。
对外控制接口按“体系”解释无名轴：

| 体系 | 机体系 x / y / z | 本地系 x / y / z | 航向 `yaw` | 偏航角速度正方向 |
|---|---|---|---|---|
| `flu`（默认） | 前 / 左 / 上 | 东 / 北 / 上（ENU，即 MAVROS `local_position`、ROS `map`） | 0° 指向 +x，逆时针为正 | 逆时针（俯视） |
| `frd` | 前 / 右 / 下 | 北 / 东 / 下（NED，PX4 内部） | 0° 指向北，顺时针为正 | 顺时针（俯视） |

换算（`relay/coords.py`，纯函数）：

- 机体 `flu (x, y, z)` = 前 x、右 −y、上 z；`frd (x, y, z)` = 前 x、右 y、上 −z。
- 本地 `flu (x, y, z)` = ENU 原样；`frd (x, y, z)` = ENU (y, x, −z)。
- 航向 `flu` yaw° → NED 航向 = 90° − yaw；`frd` 原样。
- 偏航角速度 `flu` → 顺时针 = −rate；`frd` 原样。

### 3.1 设置与请求

- 设置 `control_frame: "flu" | "frd"`，默认 `flu`，`PUT /settings` 修改（操作员）。
- `SkillBody.frame: "flu" | "frd" | "relay" | null`：本次请求的体系，缺省取设置。计划（plans）的每一步同样可带 `frame`。
- `SkillBody.reference: "body" | "local" | null`：只用于 `velocity`，缺省 `body`（`frame: "relay"` 时缺省 `local`）。
- `relay` 是 Relay 的内部轴，也是 v0.6 之前的接口约定：机体 前 / 右 / 上，本地 ENU，罗盘航向（北 0，顺时针），
  顺时针为正。`skill_started` 事件里的 `params` 总是换算成它并带 `frame: "relay"`，所以记录里的技能在任何设置下
  重飞都是同一条航线。Relay 内部生成的计划（台架流程、按记录重飞）一律用它。

### 3.2 各技能的参数

| 技能 | 受体系影响的参数 | 不受影响（有名字的方向） |
|---|---|---|
| `move` | `x, y, z`：机体系位移（米） | `forward`、`right`、`left`、`up`、`down` |
| `velocity` | `vx, vy, vz`（m/s，`reference` 决定机体系或本地系）、`yaw_rate_dps` | `seconds` |
| `goto` | `x, y, z`：本地系坐标；`yaw`：航向（度） | — |
| `yaw` | `deg`：相对转角（度，正方向同偏航角速度：`flu` 逆时针，`frd` 顺时针） | — |
| `takeoff` / `land` / `hold` / `rtl` | — | `alt` |

`move` 不能同时给 `x/y/z` 和有名字的方向（`invalid_request`）。

`velocity` 的 `reference: "body"`：Relay 以 `SET_POSITION_TARGET_LOCAL_NED`、`coordinate_frame = MAV_FRAME_BODY_NED (8)`、
`type_mask = 0x05C7`（只用速度和偏航角速度）发送，飞机转向时速度方向跟着机头转。这与 MAVROS
`setpoint_raw/local` + `FRAME_BODY_NED` 发出的帧一致（MAVROS 把 FLU 换成 FRD：`vy`、`vz`、`yaw_rate` 取反）。
安全区前瞻按当前航向把机体速度转到本地系后判断。

### 3.3 遥测 `vehicle.nav`

总是按设置的体系给出，供按 FLU / FRD 思考的 agent 直接使用；原有 `position`、`attitude`、`heading_deg` 不变。

```jsonc
"nav": {
  "frame": "flu",
  "position": [x, y, z],        // 本地系，米；没有本地位置时为 null
  "velocity": [vx, vy, vz],     // 本地系，m/s
  "body_velocity": [vx, vy, vz],// 机体系（按航向旋转的水平系），m/s
  "yaw_deg": 12.3,              // 该体系的航向
  "yaw_rate_dps": 0.0
}
```

`GET /capabilities` 增加 `control_frame`、`control_frames`（上表的机器可读形式）、`models`、`sim_frame_default`。

## 4. 速度跟踪飞法（`u7_mavros_simple.py` 的等价实现）

`takeoff`、`move`、`goto` 带 `speed`（m/s，0.1–5）时，或机型为 `anet-du7` 且有位置估计时（默认 `speed = 0.5`），
用“跟踪器”代替位置设定点（`takeoff` 的跟踪起飞只用于 PX4；ArduPilot 仍用 `NAV_TAKEOFF`）：

- 每 50 ms（20 Hz）：`v = 0.8 × 位置误差`，模长限制在 `speed`；速度矢量变化率限制 0.5 m/s²；转到机体系后以
  §3.2 的机体速度帧发送，`yaw_rate = 0`（不纠正机头；`goto` 给了 `yaw` 时先原地转向再平移）。
- 到位：水平误差 ≤ 0.20 m 且高度误差 ≤ 0.20 m 连续保持 `settle_s`（默认 2.0 s）。
- PX4 流程：POSCTL 下预发零速度 2 s → 解锁（以解锁瞬间的位置为基准）→ OFFBOARD → 爬升；与脚本相同
  （先 POSCTL 解锁，再切 OFFBOARD）。ArduPilot：GUIDED 下同样的速度帧。
- 监视（任一触发则向飞控请求一次降落，技能失败，原因写入 `skill.detail`；与脚本相同）：倾角 > 20°；
  位置跳变 > 0.25 m + 1.5 m/s × dt（估计器重置）；位置遥测超过 1.0 s 未更新（脚本在机上用 0.3 s，
  Relay 经无线链路看到的位置更晚）；实际速度 > `speed` + 0.5 m/s 持续 1 s。
- 模式被外部改走（遥控器接管）：技能失败，不再发任何设定点（与脚本的 PilotOverride 相同）。

内置计划 `du7_box`（`GET /plans/builtin`；`POST /vehicles/{id}/plan {"builtin": "du7_box"}`）：
起飞 2 m → 前 1 m → 回 → 左 1 m → 回 → 降落，即脚本的航线。

## 5. 云台吊舱

### 5.1 模型

`vehicle.gimbal: GimbalView | null`。角度采用吊舱自身的框架角约定：`yaw_deg` 右为正，`pitch_deg` 上为正
（向下看是负值），`roll_deg` 右倾为正；与 `control_frame` 无关。

```jsonc
"gimbal": {
  "kind": "sim",                       // sim：模拟吊舱；dyt：上博智像 DYT 真吊舱
  "link": "ok",                        // ok | connecting | lost
  "address": null,                     // "10.0.0.5:2000" 或串口名；模拟为 null
  "yaw_deg": 0.0, "pitch_deg": -30.0, "roll_deg": 0.0,
  "yaw_dps": 0.0, "pitch_dps": 0.0,
  "mode": "follow",                    // follow（方位跟随）| lock（电锁/姿态保持）| rate | angle | track | scan | off（电机关）
  "lens": "visible1",                  // visible1（变焦）| visible2（广角）| ir1 | ir2
  "pip": null,                         // 画中画小画面的镜头，或 null
  "zoom": 1.0,                         // 当前镜头的倍数
  "zoom_range": [1.0, 30.0],
  "digital_zoom": false,
  "fov_deg": [60.0, 35.98],            // 当前水平、垂直视场角（舞台渲染用）
  "palette": "white_hot",              // white_hot | black_hot | pseudo（红外）
  "tracking": {"state": "off", "algorithm": "auto", "x_deg": 0.0, "y_deg": 0.0, "box_px": [0, 0]},
                                       // state: off | searching | locked；algorithm: auto | person | vehicle | building
  "laser": {"on": false, "range_m": null},
  "recording": false,
  "photos": 0,                         // 本次会话拍照张数
  "motors": true, "enhance": false, "osd": true, "low_light": false,
  "selftest": {"done": true, "gyro_ok": true, "servo_ok": true, "image_ok": true},
  "target": null,                      // {"lat","lon","alt"}：吊舱解算的目标位置（DYT 表 4）
  "age_s": 0.02
}
```

镜头视场（模拟吊舱；真机无法读取时也用它估算）：`visible1` 1× 水平 60°，N 倍时 `2·atan(tan(30°)/N)`，1–30×；
`visible2` 固定 90°；`ir1` 1× 水平 40°，1–8×（电子变倍）；`ir2` 固定 24°。宽高比 16:9。

### 5.2 动作 `POST /vehicles/{id}/gimbal`

请求体 `{"action": ..., ...}`，返回 `{"id", "gimbal": GimbalView}`。权限：操作员，或正在控制该机的会话
（附身 / 有效认领）。任何飞行等级都允许（不属于飞行动作）。

| action | 参数 | DYT 指令 |
|---|---|---|
| `rate` | `yaw_dps`、`pitch_dps`（±100，持续到 `stop` 或新指令） | 0x24，0.1°/s |
| `stop` | — | 0x24 全零 |
| `angle` | `yaw_deg`（±180）、`pitch_deg`（−120…+90）、`space: "frame" \| "earth"`（缺省 frame） | 0x26 / 0x3b，0.01° |
| `center` | — | 0x2b |
| `follow` | `on` | 0x2a / 0x29 |
| `lock` | `on` | 0x30 / 0x31 |
| `motors` | `on` | 0x27 / 0x28 |
| `zoom` | `level`（倍） | 0x5a，0.1 倍 |
| `zoom_rate` | `rate`（−100…100，0 停止） | 0x25 |
| `digital_zoom` | `on` | 0x58 / 0x59 |
| `lens` | `lens`、`pip`（可选，镜头名或 null） | 0x01–0x04 + 参数 3 |
| `palette` | `palette` | 0x11 / 0x12 / 0x50 |
| `photo` | — | 0x5b |
| `record` | `on` | 0x09 / 0x0a |
| `track` | `x`、`y`（像素，图像中心为 0）、`algorithm`（可选） | 0x0d，0x13–0x16 |
| `track_stop` | — | 0x0e |
| `laser` | `on` | 0x2d / 0x2e |
| `focus` | `mode: "auto" \| "manual"`、`position`（手动，4090…49152） | 0x5c / 0x5d |
| `enhance` / `osd` / `low_light` | `on` | 0x05/0x06、0x51/0x52、0x56/0x55 |
| `scan` | `yaw_deg`、`pitch_deg`、`speed_dps` | 0x32 |
| `scan_stop` | — | 0x33 |
| `geo_track` | `lat`、`lon`、`alt`；或 `mode: "center" \| "exit"` | 0x3a |
| `look_at` | `x, y, z`（本地系，按 `frame` / 设置的体系） | Relay 解算后发 `angle`（space earth） |

其他接口：

- `GET /vehicles/{id}/gimbal` → `GimbalView`（没有吊舱时 404 `gimbal_missing`）。
- `POST /vehicles/{id}/gimbal/attach {"transport": "tcp", "host", "port": 2000}` 或
  `{"transport": "serial", "device", "baud": 115200}`（操作员；真机）。模拟机：`{"transport": "sim"}`。
- `DELETE /vehicles/{id}/gimbal`（操作员）。
- `GET /vehicles/{id}/gimbal/captures?limit=` → 拍照 / 录像记录：时间、飞机位姿（`nav`）、云台角、镜头、倍数、
  激光测距、目标位置。

事件：`gimbal_attached`、`gimbal_detached`、`gimbal_link`（ok / lost）、`gimbal_capture`（photo）、
`gimbal_record`（on / off）、`gimbal_lens`。错误码：`gimbal_missing`、`gimbal_offline`、`gimbal_unsupported`
（该吊舱没有这个能力，如 `micro` 的模拟机）、`gimbal_busy`。

### 5.3 DYT 协议（`relay/gimbal/dyt.py`）

- 指令帧 16 字节：`EB 90`、控制码、参数 X（S16 LE）、参数 Y（S16 LE）、参数 3（U8）、变焦速率（S8）、6 字节保留、
  校验和（0–14 字节之和的低 8 位）。文档示例必须逐字节通过单元测试，例如
  “以 10°/s 向右旋转”= `EB 90 24 64 00 00 00 00 00 00 00 00 00 00 00 03`，
  “转到方位 10°、俯仰 −10°”= `EB 90 26 E8 03 18 FC 00 … A0`，“变焦到 5 倍”= `EB 90 5A 32 00 00 00 00 32 … 39`。
- 遥测帧 32 字节 `EE 16`（60 Hz）：状态位、变焦倍数（12 位，0.1 倍）、大小画面、脱靶量（0.05°）、
  横滚 / 俯仰 / 方位框架角（0.01°）、角速度（0.01°/s）、激光测距（0.1 m，0 无效）、自检。
- 载机姿态帧 32 字节 `EB 91`：Relay 以 10 Hz 把飞机姿态、经纬度、高度、时间发给吊舱（目标解算、数引需要）。
- 目标位置帧 `EE 18`、单次状态返回 `EE 19`。
- 网络控制：TCP 连吊舱 2000 端口，外层 `EB 90 <N> <数据 N 字节> <校验和：数据之和低 8 位>`；吊舱返回原协议。
- 串口：115200 8N1，直接收发原协议。
- 流式解析器按同步字和校验和重新同步；校验失败计数进入 `gimbal` 调试信息。

### 5.4 模拟吊舱（`relay/gimbal/sim.py`）

- 一阶角速度响应（时间常数 0.08 s，最大 100°/s），俯仰限位 −120°…+90°，方位 ±180° 连续。
- `follow`：方位随机头；`lock`：保持地理指向；`angle` / `rate` / `scan` / `track` 如表。
- 变焦以 2 倍/秒的速度趋近目标倍数；`zoom_rate` 按比例连续变焦。
- 激光测距：沿视线与地面（z = 0）和世界里的环、障碍求交，最大 1200 m。
- `track`：锁定画面中的点对应的地面点，之后保持指向它（地理锁定）。
- 目标位置：有激光测距时给出本地坐标对应的经纬度（模拟机的 home）。
- 与物理同一时钟（`sim.world` 步进），确定性。

### 5.5 舞台与界面

- ANetDU7 模型 `web/public/models/anet_du7.glb`：真实尺寸，节点 `Propeller_{FL,FR,RL,RR}_ROTATABLE`（绕本地 Y 轴转）、
  `Gimbal_Yaw` → `Gimbal_Pitch` → `Gimbal_Camera`（镜头朝本地 +Z，Y 向上，与机头同向）。舞台按 `vehicle.gimbal`
  转动这两个节点。
- 云台画面（画中画）：从 `Gimbal_Camera` 的位姿用 `fov_deg` 渲染舞台场景；红外镜头用灰度 / 伪彩后处理；
  叠加十字、倍数、镜头名、测距、跟踪框。`photo` 事件时前端保存该帧缩略图。
- 检视器“云台”组：方向盘（rate）、归中、镜头切换、变焦滑条、拍照、录像、跟随 / 锁定、激光、红外色板。
- 添加模拟机对话框：机型选择（ANetDU7 默认 / Micro 120 / 250 / 450）。
- 设置：坐标体系（FLU / FRD）。

## 6. 真机接入

ANetDU7 机载的 MAVROS 以 `gcs_url:=udp://:14550@<Relay 主机 IP>:14550` 启动（`start_drone.sh` 已有这一项），
Relay 在 UDP 14550 上发现它，与其他 MAVLink 飞机相同。机载的定位（FAST-LIO → `/mavros/vision_pose/pose`）、
避障规划继续在机上运行；Relay 负责群控、附身、agent 接口。多机时每架飞机的 `MAV_SYS_ID` 必须不同。
吊舱经机载网口（J30-9ZKP 6–9 脚）接入机载交换，Relay 直接连它的 TCP 2000。详见 `vehicles/anet-du7/README.md`。

## 8. 验收

1. 启动后点 Add sim：舞台出现 ANetDU7，PX4 风格，自带吊舱；`micro-120` 仍可选。
2. `POST /vehicles/{id}/skills {"name":"velocity","vx":0.5,"seconds":2}`：飞机沿机头方向前进（FLU 默认）；
   `{"vy":0.5}` 向左；`frame:"frd"` 时 `vy` 向右、`vz` 向下。
3. 内置计划 `du7_box` 在 ANetDU7 模拟机上飞完，四个到位点误差 ≤ 0.2 m。
4. `POST /vehicles/{id}/gimbal`：`angle`、`rate`、`zoom`、`lens`、`photo`、`record` 改变 `vehicle.gimbal` 并发事件；
   DYT 编码与协议文档示例逐字节一致；对回放的假吊舱（TCP）能挂接、读遥测、发指令。
5. 舞台：云台节点随 `gimbal` 转动；云台画中画随变焦改变视场，切镜头改变画面风格。
6. 原有测试全部通过；对战、评测、内置程序行为不变。

## 9. 已知限制

- 真吊舱的视频流（H.264，含 SEI）不在本版本解码；画中画只对模拟吊舱渲染，真机可绑定采集卡 / UVC 源。
- 物理预设的转动惯量、推力曲线来自同级别机型的经验值，未用真机辨识；固件孪生用真机参数时悬停油门会对齐。
- `nav` 的本地系原点是飞控的本地原点；室内以 FAST-LIO 建图原点为准，多机之间没有统一原点（需要各机手工对齐）。
