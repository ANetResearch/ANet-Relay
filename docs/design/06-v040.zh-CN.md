# 06 v0.4.0：机载程序、状态机对抗、只用摇杆的控制、真实机体缺陷、Copilot 编程、开屏改序与凭据存储（设计 v1.0，2026-11-08）

本文是 v0.4.0 的约束性契约，补充 01–05；与 05 冲突之处以本文为准（05 §2.3 开屏时间线、05 §2.2 影片清单已加注指向本文）。所有接口位于 `/api/v1`，错误体沿用 03 §10。

## 1. 问题与思路：把"智能"放到飞机上

**问题。** 大语言模型智能体的一次决策需要数百毫秒到数十秒；一架四旋翼要保持稳定、要躲避、要瞄准，控制回路需要 50 Hz 以上。让智能体逐帧推杆在时间尺度上就不可行；把它换成"往前飞 10 m"之类的高层接口虽然可用，却等于把飞行这件事本身从智能体手里拿走了——它不再面对重心偏、油门不够、电压下降这些真实问题。

**思路：三个时间尺度，各司其职。**

| 层 | 频率 | 由谁实现 | 本版的位置 |
|---|---|---|---|
| 反射层：姿态自稳、电机混控 | 250 Hz 以上 | 飞控（真机）/ 模拟飞控（模拟机） | 已有；本版只给模拟机加入真实缺陷（§4） |
| 行为层：**机载程序**（状态机） | 50 Hz | 人或智能体写的代码，在本机隔离运行，输入观测、输出摇杆 | 本版核心（§2、§3） |
| 决策层：智能体 | 秒到分钟 | Copilot / 外部智能体 | 写程序、改程序、调参数、跑测试与对抗、读日志与回放（§6） |

智能体不再"开飞机"，而是"给飞机写大脑"：它写出一段把观测映射为摇杆的程序，程序在机载回路里以 50 Hz 运行；智能体以自己的节奏观察程序的状态、日志与成绩，修改代码或实时调整程序公开的参数。程序与程序之间在对抗场里比赛，因此能看到流畅的小飞机作战，而胜负取决于谁写的"大脑"更好。

**硬约束：只用摇杆。** 无论是程序、智能体还是外部代码，飞行控制的唯一输出是四个摇杆量（横滚、俯仰、偏航、油门）外加遥控器上本来就有的离散开关（解锁、模式开关、射击）。"起飞到 1 m""前进 1 m""去某点"这类高层接口对智能体与程序关闭（§5），智能体必须和人一样面对悬停不稳、油门不足的问题。

## 2. 机载程序（Programs）

### 2.1 程序是什么

一个程序是一段受限 Python（§2.4）源码，带名称、说明、版本历史、可调参数与测试用例。它导出两个函数：

```python
PARAMS = {"target_alt": 1.2, "aggression": 0.5}   # 可实时调整的参数（数值 / 布尔 / 短字符串）

def init(ctx):
    """部署时调用一次。ctx.mem 是跨帧保留的字典。"""
    ctx.state = "climb"          # 当前状态名，显示在舞台标签与检查器中

def step(obs, ctx):
    """每 20 ms 调用一次（50 Hz）。必须返回 Sticks。"""
    if ctx.state == "climb":
        thr = 0.55 + 0.4 * (ctx.params["target_alt"] - obs.alt) - 0.15 * obs.vz
        if abs(obs.alt - ctx.params["target_alt"]) < 0.1:
            ctx.state = "hold"
        return Sticks(throttle=clamp(thr, 0, 1))
    ...
```

- `Sticks(roll=0, pitch=0, yaw=0, throttle=0, fire=False)`：roll/pitch/yaw ∈ [−1, 1]，throttle ∈ [0, 1]，与人的手柄同一坐标系（03 §5.2）。超界截断，非有限值视为本帧失败。
- `ctx`：`mem`（字典）、`params`（只读视图，随实时调参更新）、`state`（字符串 ≤ 32）、`log(*args)`（写入日志环，每帧最多 4 行）、`t`（部署后秒数）、`rng`（以部署种子初始化的确定性随机数）。
- 返回 `None` 或抛出异常：本帧输出"安全杆量"（姿态回中、油门保持上一帧），计一次故障；连续 25 次（0.5 s）故障 → 程序进入 `faulted`，控制交还安全层（§2.6）。

### 2.2 观测（`obs`，只包含机载能得到的东西）

| 字段 | 单位 | 说明 |
|---|---|---|
| `t`、`dt` | s | 程序时间、本帧间隔 |
| `armed`、`airborne`、`mode` | — | 解锁、离地（着陆检测）、飞控模式名 |
| `roll`、`pitch`、`yaw` | deg | 姿态（ATTITUDE），yaw 为航向 0–360 |
| `p`、`q`、`r` | deg/s | 机体角速度 |
| `ax`、`ay`、`az` | m/s² | 机体加速度（模拟机给出；真机有 `SCALED_IMU`/`HIGHRES_IMU` 时给出，否则 `None`） |
| `alt`、`vz` | m、m/s | 气压高度（相对起飞点）与垂直速度；无气压计时为 `None` |
| `pos`、`vel` | m、m/s（ENU） | 仅当有定位源时；模拟机由场景决定（§3.3），带噪声与 10 Hz 更新 |
| `battery` | `{v_cell, pct}` | 每节电压与估计电量 |
| `throttle_out` | 0–1 | 飞控实际输出的平均电机量 |
| `hp`、`ammo`、`reloading` | — | 对抗场中的生命值、弹药、装填中；非对抗场为 `None` |
| `contacts` | 列表 | 传感器"看到"的其他飞机：`{id, team, dist, bearing, elevation, rel:(fwd, right, up), vrel:(fwd, right, up), hp}`，机体航向坐标系，带噪声，30 m 内，最多 16 个 |
| `arena` | `{radius, floor, ceiling}` | 场地边界（对抗场与题目中） |
| `sticks_in` | Sticks | 人的手柄当前量（人与程序共驾模式下，§2.6） |

观测是只读数据对象（属性访问），在后端由同一构造器从车辆状态生成；模拟机与真机同构，真机缺失的量为 `None`。程序控制的飞机，Relay 自动把 `ATTITUDE` 提到 50 Hz、`LOCAL_POSITION_NED` 提到 20 Hz（真机按数传余量，失败则保持原速率并在检查器提示）。

### 2.3 状态机辅助

标准库模块 `relay`（程序中直接可用，无需导入）：

- `clamp(x, lo, hi)`、`wrap180(deg)`、`lerp`、`deadband(x, d)`、`lowpass(prev, x, alpha)`
- `PID(kp, ki, kd, i_limit, out_limit)`：`pid.step(error, dt)`、`pid.reset()`
- `StateMachine(initial)`：`sm.add(name, fn)`，`fn(obs, ctx) -> (Sticks, next_state | None)`；`sm.step(obs, ctx)` 运行当前状态、处理转移、维护 `ctx.state`、记录转移次数与驻留时间（用于检查器显示）
- `Timer`：`ctx.mem` 中的计时辅助

### 2.4 语言与隔离

- 语言：Python 3 语法的子集，由 AST 白名单校验后编译执行。允许：函数定义（无装饰器）、赋值、`if/for/while/break/continue/pass/return`、`try/except Exception`、表达式、推导式、lambda、f-string、`assert`、`math` 模块（`import math` 或 `from math import ...` 唯一允许的导入）。禁止：其他所有 `import`、类定义、`global/nonlocal`、`with`、`yield/async`、任何以 `_` 开头的名称或属性、`exec/eval/compile/open/getattr/setattr/globals/locals/vars/dir/type/__import__/input/breakpoint`。内置函数白名单：`abs min max round sum len range enumerate zip sorted reversed int float bool str list dict tuple set isinstance any all map filter divmod pow print`（`print` 写入日志）。源码 ≤ 64 KB。
- 执行：独立子进程"程序宿主"（`relay.programs.host`，冻结后端以 `--program-host` 参数重新启动自身），每次部署一个宿主进程（集成修订：同一进程内的程序可以借共享对象互传数据、以栈溢出崩溃整个宿主或耗尽彼此的时间与内存，故按部署隔离；宿主在 API 线程上启动并加载，加载失败不影响正在飞行的程序）；后端机群线程每 20 ms 同时向各宿主发送观测、在同一时限内收集输出（管道，定长帧），从不在宿主上阻塞（停止、急停与附身先释放杆量，宿主随后被终止；实时调参随下一帧发送）。单个程序单帧预算 2 ms（软限，超出计数），宿主每批 15 ms 未返回 → 本帧使用安全杆量；连续 3 批超时 → 杀死该宿主，该程序标记 `faulted`；宿主在两帧之间退出则重启并重新加载（`ctx.mem` 清空）。POSIX 上宿主设置 `RLIMIT_AS`（512 MB）、`RLIMIT_CPU` 并降低优先级（Windows 以低于正常的优先级启动）；后端在所有平台上从进程外读取宿主常驻内存，超过 512 MB 即终止该宿主，程序以 `memory` 故障结束。宿主没有网络、文件访问能力（语言层禁止导入，进程层不继承任何句柄）。
- 来源：程序只来自本机（界面编辑、Copilot、本机 API）；局域网对抗只交换飞行状态（05 §7），从不交换代码。

### 2.5 存储与版本

- 程序保存在 `<data_dir>/programs/<id>.json`：`{id, name, description, source, params, tests, created, updated, revisions:[{rev, source, params, author, note, t}]}`，保留最近 50 个版本；作者为 `operator` 或会话名（智能体）。
- 内置示例程序（只读，可复制）：`hover_trim`（带积分修正的悬停）、`liftoff`（油门搜索起飞）、`patrol`（无定位源的定时转向巡逻）、`hunter_easy` / `hunter_medium` / `hunter_hard`（三档对抗机器人状态机：搜索 → 接近 → 射击 → 规避）。

### 2.6 部署与安全

- 部署：`POST /vehicles/{id}/program {program, rev?, params?, mode: "pilot" | "copilot"}`。`pilot`：程序独占摇杆；`copilot`：人的手柄量作为 `obs.sticks_in` 输入，程序输出替代之（例如写一个"自动配平"辅助）。
- 权限：操作员或该飞机的控制者（认领的会话）。部署后程序以"程序控制者"身份持有摇杆（时间线显示为 `PROGRAM · <name>`，与人、智能体区分）。
- 人永远优先（03 §4 不变）：人附身 → 程序立即暂停（输出停止），释放后不自动恢复，需重新 `resume`。
- 急停、链路丢失、坠毁 → 程序停止。杆量超时 0.8 s 的规则不变（宿主挂起即触发）。
- 真机：缺省禁止。检查器中 `Allow programs on this aircraft`（操作员开启，确认词 `PROGRAM`，每次连接重置）+ 起飞前检查通过才可部署；真机上程序的 `fire` 输出被忽略。
- 运行视图（快照 `vehicle.program`）：`{id, name, rev, state, status: running|paused|faulted|stopped, fps, faults, last_error, mode}`；日志 `GET /vehicles/{id}/program/log?after=`（环 500 行）。
- 实时调参：`PATCH /vehicles/{id}/program/params {name: value}`（类型与范围按 `PARAMS` 缺省值推断，字符串 ≤ 32）——这是智能体在慢时间尺度上影响快回路的主通道。

## 3. 题库与对抗（像刷题一样写飞行程序）

### 3.1 单元测试（固定输入输出）

程序可附带 `tests`：`[{name, obs: {...部分字段}, mem?: {...}, state?: str, expect: {roll?: [lo, hi], pitch?: [lo, hi], yaw?: [lo, hi], throttle?: [lo, hi], fire?: bool, state?: str}}]`。`POST /programs/{id}/test` 在宿主中逐条执行 `step`（未给出的观测字段取"悬停在 1 m、姿态水平"的缺省值），返回每条的实际输出与通过与否。编辑器"测试"页一键运行，像 LeetCode 的样例。

### 3.2 题目（固定场景的飞行判题）

题目是确定性场景 + 判分规则，在**无头评测器**中以快于实时的速度运行（§3.4），每题有可见样例种子与隐藏种子（隐藏种子的机体缺陷不同，防止只对一个种子调参）：

| id | 名称 | 场景 | 通过条件 |
|---|---|---|---|
| `liftoff` | 起飞 | 载重使悬停油门约 0.62；无定位源 | 5 s 内离地并在 1.0 ± 0.2 m 保持 3 s |
| `hover` | 悬停 | 重心前偏 + 水平校准误差；有气压计、无定位源 | 20 s 内水平漂移 ≤ 0.8 m、高度 1.0 ± 0.25 m（判分用真值） |
| `heading` | 定向 | 电机效率不一致导致偏航漂移 | 15 s 航向误差 ≤ 10° |
| `square` | 方形航线 | 有 UWB 式定位（10 Hz，σ 5 cm） | 按序经过四角（半径 0.4 m），用时越短分越高 |
| `rings` | 穿环 | 现有穿环航线（03 §8） | 全部过环，计时 |
| `pursuit` | 追踪 | 一架按脚本飞行的目标机 | 60 s 内保持在目标 2 m 内的时间比例 |
| `duel_easy` / `duel_medium` / `duel_hard` | 决斗 | 对手为内置机器人程序 | 胜利（击落对手且自身存活），平局按剩余生命值 |

分数 0–100，每题记录最好成绩与提交历史（`<data_dir>/programs/results.json`）。

### 3.3 场景参数

每个场景（题目、对抗、手动部署到模拟机）给出：`airframe`（§4 的缺陷参数或预设 + 种子）、`sensors`（`baro: bool`、`position: none | uwb | gps`、`contacts: bool`）、`arena`（半径 / 地板 / 天花板）、`hover_assist: false`（题目与对抗一律关闭，05 §5）、`duration_s`、出生点。

### 3.4 无头评测器与锦标赛

- 评测器在独立子进程中构造一个隔离的 `FleetService`（`listen=False`、`History(None)`、注入时钟），用与实时相同的模拟飞控、摇杆路径、对抗规则与程序宿主逻辑，以最快速度推进，目标 ≥ 10 倍实时；同一 `(场景, 种子, 程序版本)` 结果完全确定。
- `POST /challenges/{id}/submit {program, rev?}` → 评测任务（异步）；`GET /jobs/{id}` → `{state, progress, result: {score, passed, metrics, seeds:[...], trace_id}}`。
- 对抗：`POST /duels {programs: [id...2..8], rounds, seed, scenario?}` → 评测任务；结果含每局胜负、命中、存活时间与 Elo 排名表（`<data_dir>/programs/ladder.json`）。
- 轨迹：每局保存降采样轨迹（10 Hz，全部飞机），`GET /traces/{id}` 返回；界面可在舞台中回放（多机回放，复用 05 的场地渲染与子弹层）。
- 实时对抗：把程序部署到本机多架模拟机，在对抗场（05 §7）中实时进行；局域网中其他终端部署的程序也在同一场地——不同终端的程序真正"PK"。
- 并发：同时最多 2 个评测任务（每个一个子进程），排队其余；评测进程退出时清理。

## 4. 真实机体缺陷（模拟机）

在 05 §5 的物理模型之上加入"装配误差"，**只在悬停辅助关闭时生效**（辅助开启的回归测试不变）：

| 参数 | 含义 | 效果 |
|---|---|---|
| `mass_kg` / `payload_kg` | 起飞重量 | 悬停油门上升；超过推力上限则飞不起来 |
| `cg_offset_cm (x, y)` | 重心偏移 | 姿态环需持续差动补偿：自稳模式下产生持续的小倾角（积分项按 2 s 时间常数修正其 70 %，剩余 30 % 为稳态倾角）→ 飞机持续向重心偏移方向漂移；大偏移时电机饱和、可控性下降 |
| `level_trim_deg (roll, pitch)` | 水平校准误差 | 飞控认为"水平"时实际倾斜该角度 → 杆量回中仍漂移 |
| `motor_gain[4]` | 各电机效率（±8 %） | 偏航漂移与倾斜扰动 |
| `prop_damage` | 某桨受损程度 0–1 | 振动增加、该电机推力下降 |
| `imu_noise` | 姿态与加速度噪声倍数 | 观测更"脏" |

- 预设：`ideal`（全零）、`typical`（缺省：小偏差，种子随机）、`rough`（明显偏差，新手难以悬停）、`custom`。按种子确定性生成。
- 接口：`PUT /sims/{vid}/airframe {preset | params, seed?}`；快照 `vehicle.sim.airframe`（只给预设名与种子，具体数值在检查器"机体"页展开，程序观测中**不包含**这些数值——要靠飞出来）。
- 界面：检查器新增"机体"分组（模拟机）：预设选择、种子、各参数滑块、`Randomize`。
- 真机无此项。

## 5. 只用摇杆：智能体控制等级

- 新设置 `agent_flight_level`：`sticks`（缺省）/ `full`。只能由操作员修改（Settings → Safety）。
- `sticks` 等级下，会话（智能体、外部代码、Copilot）对飞行的可用操作只有：摇杆（WebSocket 50 Hz 流、`POST /vehicles/{id}/sticks` 单帧、`sticks` 技能"保持杆位 N 秒"）、解锁 / 上锁、切换**手动类**模式（STABILIZE / MANUAL / ACRO）、射击、程序（§2、§3）以及安全动作（急停、`land` 仅作为安全动作保留，事件中标注 `safety`）。`takeoff`、`hold`、`move`、`yaw`、`goto`、`rtl`、`velocity`、`attitude` 技能，含这些动作的动作序列，以及切换到定高 / 定点 / 自动类模式，对会话返回 403 `sticks_only`（`detail.level = "sticks"`）。
- 操作员（人在界面上）不受此等级影响。
- MCP：飞行服务器在 `sticks` 等级下的工具列表只列出允许的工具（`tools/list` 每次读取当前设置）；`full` 等级恢复 v0.3 的全部工具。设备服务器、应用服务器不变（设备级的电机测试、校准等仍受 04 的确认词约束）。
- Copilot 的系统提示与工具集同步：在 `sticks` 等级下明确告诉模型"你只能通过摇杆或程序控制飞行，高层接口不可用；稳定飞行请写程序"。

## 6. Copilot 与智能体的编程能力

新增工具（Copilot 内置工具、应用 MCP 服务器、SDK 同步）：

| 工具 | 作用 |
|---|---|
| `program_list` / `program_get` | 列出 / 读取程序（含源码、参数、测试、版本） |
| `program_create` / `program_update` | 新建 / 修改程序（`update` 支持整体替换与基于行号的补丁；每次产生新版本，附 `note`） |
| `program_validate` | 只做 AST 校验，返回错误行列与原因 |
| `program_test` | 运行单元测试（§3.1） |
| `program_deploy` / `program_stop` / `program_resume` | 部署到飞机、停止、恢复（受 §2.6 权限与真机门槛约束） |
| `program_params` | 实时调参 |
| `program_status` / `program_log` | 运行状态与日志 |
| `challenge_list` / `challenge_submit` / `job_status` | 题目与评测 |

## 9. Copilot 凭据存储（不再触发钥匙串）

**现状。** Copilot 用 Electron `safeStorage` 加密 API 密钥；在 macOS 上它使用登录钥匙串中的 "ANet Relay Safe Storage" 条目，查询可用性与解密都会触发系统的钥匙串授权对话框（应用签名变化后还会再次询问）。用户感到"应用想要我的密码"。

**改为：**

- 缺省存储：应用数据目录中的 `copilot-secrets.json`，文件权限 0600（Windows 为仅当前用户的 ACL），内容以每次安装随机生成的 256 位密钥做 AES-256-GCM 加密（密钥文件 `copilot-secrets.key`，同样 0600）。这能防止密钥以明文出现在备份与日志中；对能以本人身份读文件的程序不构成保护——设置中如实说明：`Stored in the app data folder and readable only by your user account.` / `保存在应用数据目录，仅当前系统用户可读。`
- 可选：Settings → Copilot → `Store keys in the system keychain`（macOS 钥匙串 / Windows 凭据加密 / Linux Secret Service），缺省关闭；只有开启后才会调用 `safeStorage`。
- 绝不在启动、打开 Copilot、查询状态时调用 `safeStorage`（`isEncryptionAvailable` 也不调用），除非上述选项开启。
- 迁移：已有 `keyEnc`（存于钥匙串加密）的用户升级后，不自动解密；Copilot 面板显示一行说明 `Your saved key is protected by the system keychain. Enter it again to store it in the app data folder, or keep using the keychain.` 与两个按钮 `Enter key again` `Keep using keychain`（后者开启选项）。
- 文档与设置页说明：Relay 不读取、不需要系统登录密码；钥匙串对话框来自操作系统，只有在用户选择用钥匙串保存密钥时才会出现。
- 实现说明（WP-4a）：存储逻辑在 `electron/copilot/config.mjs`（纯 Node，`safeStorage` 以惰性函数注入，测试 `electron/test/secrets.test.mjs` 以计数桩验证缺省配置零调用）。Windows 采用 ACL 方案而非 DPAPI 回退：两个密钥文件与 `copilot.json` 写入后执行 `icacls <file> /inheritance:r /grant:r <域>\<用户>:F`（去掉继承的 SYSTEM / Administrators），失败时保留用户配置文件目录本身的 ACL 并记录日志；DPAPI 虽不弹窗，但它就是 `safeStorage`，缺省使用会违反"非选项开启不调用"的约束。`copilot.json` 新增 `keyStorage: "file" | "keychain"`；旧版只有 `keyEnc` 而无 `keyStorage` 视为待迁移（`keyMigration: "keychain"`，不解密、`hasKey: false`）；旧版 `keyPlain`（无钥匙串系统上的 0600 明文）在首次读取时直接移入加密文件。钥匙串模式下状态查询也不解密（`keyHint` 在保存时记录），只有构建智能体与测试连接时才解密；切换存储方式时由用户操作触发一次迁移。
