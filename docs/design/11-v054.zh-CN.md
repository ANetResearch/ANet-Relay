# 11 · v0.5.4：固件孪生（SITL）、硬件在环（HITL）、特技模式与摔机翻滚

日期：2026-11-09（UTC）。基线：v0.5.3（32adfd8）。本文件是 v0.5.4 的实现契约；与 01–10 冲突处以本文件为准。

## 0. 来源

操作员在 v0.5.3 上测试模拟机后提出：

1. 调了重心却看不到机身前倾；模拟机从不翻飞，摔下来也不会滚动，不够真实。
2. 特技模式（可翻滚、倒飞、侧飞）与摔机翻滚都要做。
3. 以前用 Mission Planner 的“模拟”功能，把飞控通过 USB 接到电脑，用真实飞控和它的参数做仿真；希望 Relay 也能做到，且一步到位。
4. 飞机固件不能改。不能假定实际飞机是 PX4 还是 ArduPilot，两者都要支持；当前小机是 Pixracer + ArduPilot，后面的大机是 PX4。
5. 飞控程序全部随安装包分发，按优先级多带几个版本，尽量不外部下载；以后需要大量版本时再放到 GitHub Release / ModelScope。
6. Relay 要自己发现飞机的固件并适配，至少支持手动选择。

## 1. 结论与效果

| 引擎 | 大脑 | 物理 | 用途 | 小机（ArduPilot） | 大机（PX4） |
|---|---|---|---|---|---|
| 快速模拟（现有，升级） | Relay 的飞控行为模拟 | Relay 六自由度 | 多机、裁判与天梯、CI，可快于实时 | 可用 | 可用 |
| **固件孪生（SITL）** | 官方固件的电脑版本，与真机**同版本**，加载真机**参数** | Relay 六自由度 | 真实控制回路、预检、失控保护与参数效果；调序列、调参数 | 可用 | 可用（Windows 除外，§3.2） |
| **硬件在环（HITL）** | **真机飞控板**本身 | Relay 六自由度，经 USB 喂传感器；电机被固件锁死 | 检验这块板子的固件、参数与计算时序 | 不可用（§7.1） | 可用（临时改参数，自动恢复） |

三种引擎共用同一个物理世界（§8）：可配置机型、带噪声的传感器、刚体触地与摔机翻滚。快速模拟另外获得特技模式（§8.4）。对 Relay 的其他部分，孪生与 HITL 都是一架模拟机：API、时间轴、程序、Copilot 与 MCP 不变。

已在本机验证（2026-11-09，原型脚本在 scratchpad）：

- 官方 ArduCopter 4.7.2 SITL（静态链接的 Linux 二进制）经 JSON 接口与 Relay 物理锁步：解锁、爬升、定高 3.16 m、1 m/s 下降、落地；固件估计高度与真实高度一致到 2 cm。
- 自编译 PX4 v1.16.2 SITL（`none_iris`）经 MAVLink HIL 锁步：解锁、Takeoff detected、定高、Landing detected、Disarmed by landing。
- 经验：传感器必须带噪声（PX4 会把恒定读数判为卡死）；参数必须与机型匹配（为 1.5 kg Iris 调的增益在 120 g 机型上会振荡）；PX4 SITL 默认把地面站链路发到 UDP 14550，与 Relay 监听真机的端口冲突，必须改走专用端口（§6.2）。

## 2. 架构

```
Relay 安装包（含飞控运行包，§3）
├─ 快速模拟：sim/autopilot.py（行为模拟）── sim/physics.py
└─ 孪生模块 relay/twin/（按需加载，进程按需启动）
     ├─ packs.py      运行包索引：列出 / 校验 sha256 / 导入 / 删除
     ├─ identity.py   真机固件识别与匹配（§4）
     ├─ profile.py    孪生配置：固件身份 + 参数 + 机型（§5）
     ├─ params.py     参数过滤（硬件相关项不进孪生）
     ├─ ardupilot.py  ArduPilot SITL 进程 + JSON 桥（§6.1）
     ├─ px4.py        PX4 SITL 进程 + HIL 桥（§6.2）
     ├─ hil.py        HIL 报文编码（HIL_SENSOR / HIL_GPS / HIL_ACTUATOR_CONTROLS），SITL 与 HITL 共用
     ├─ hitl.py       PX4 硬件在环会话：备份、写参数、重启、运行、恢复、核对（§7）
     └─ autopilot.py  TwinAutopilot：对 SimDriver 呈现与 SimAutopilot 相同的接口
```

- **接口形状不变**：`drivers/sim.py::SimDriver` 用 `receive(bytes, now)` / `step(now) -> bytes` 与模拟飞控交换 MAVLink 字节。`TwinAutopilot` 实现同样的接口：把 Relay 发来的 MAVLink 转给固件进程（回环 TCP/UDP），把固件发出的 MAVLink 交回 Relay；它持有一个 `physics.Quad`，世界碰撞、竞技场、机体面板与舞台照常使用。
- **锁步在 tick 内完成**：每次 `step(now)`，`TwinAutopilot` 把固件时间推进到 `now`：ArduPilot 每帧收一个 PWM 包、回一帧 JSON；PX4 每帧发一个 `HIL_SENSOR`、收一个 `HIL_ACTUATOR_CONTROLS`。固件只随 Relay 的时钟前进，因此测试的步进时钟、裁判的加速都成立；不另开线程。
- **网络边界（修订 03 §6.1 H7）**：孪生只使用回环地址 127.0.0.1 上的端口，绝不监听其他网卡，也不向外发包；固件进程以 Relay 子进程启动，Relay 退出、删除模拟机或复位时结束它。HITL 走串口，不经网络。
- **端口**：实例号 `n` 从 0 起按孪生分配。ArduPilot：MAVLink TCP `5760 + 10n`，JSON 物理 UDP `9002 + 10n`；PX4：HIL TCP `4560 + n`（Relay 监听，PX4 连入），地面站 UDP 本地 `18570 + n`、对端 `24550 + n`（Relay 专用，不用 14550）。启动前检查端口可用，不可用时换下一个实例号。

## 3. 飞控运行包

### 3.1 内容与随包版本

一个运行包是一种固件、一个版本、一个平台的目录：

```
resources/autopilots/
  index.json                         # 本平台所有包：id、固件、版本、git、平台、大小、sha256、许可、源码链接
  ardupilot-copter-4.7.2/
    manifest.json
    bin/arducopter(.exe) [+ cygwin DLL]
    defaults/copter.parm             # 该版本 Tools/autotest/default_params/copter.parm
    defaults/relay-quadx.parm        # FRAME_TYPE 1 等 Relay 基线
  px4-1.16.2/
    manifest.json
    bin/px4
    etc/                             # ROMFS（init.d-posix、airframes、mixers），含 Relay 的 px4-rc.mavlink（§6.2）
```

随包版本（按真机可能性与支持期排序）：

| 固件 | 版本 | linux-x64 | mac-arm64 / mac-x64 | win-x64 |
|---|---|---|---|---|
| ArduCopter | 4.7.2、4.6.3、4.5.7、4.4.4、4.3.8 | 官方 SITL 二进制（firmware.ardupilot.org） | CI 用 waf 编译 | CI 用 Cygwin 编译（ArduPilot 官方方法） |
| PX4 | v1.17.0、v1.16.2、v1.15.4、v1.14.4 | CI 编译 | CI 编译 | 不提供（PX4 SITL 不支持原生 Windows） |

实测体积：ArduCopter SITL 7.2 MB，压缩后 3.0 MB；PX4 SITL 去符号后 4.8 MB，压缩后 2.3 MB，ROMFS 0.14 MB。九个包使每个安装包增大约 25–30 MB（Windows 只含 ArduPilot，约 20 MB）。某个版本在某平台编译失败时，该平台不带该版本，`index.json` 与文档如实列出。

### 3.2 构建与分发

- `.github/workflows/autopilots.yml`（手动触发）按平台 × 版本构建运行包，发布到本仓库的 Release `autopilots-v1`（资产：`<id>-<platform>.tar.gz` 与 `index-<platform>.json`）。ModelScope 作为镜像，后续需要时同步，不在本版强制。
- `release.yml` 在打包前下载本平台全部运行包到 `build/autopilots/`，经 electron-builder `extraResources` 放入 `resources/autopilots`。macOS 上运行包里的可执行文件随应用一起签名、公证。
- 开发环境：`scripts/fetch-autopilots.mjs` 把本平台的包下载到 `var/autopilots/`（不入库）；后端按 `RELAY_AUTOPILOTS_DIR` → 打包资源目录 → `var/autopilots` 的顺序查找。
- 许可：ArduPilot 为 GPLv3，PX4 为 BSD-3。运行包作为独立程序分发，`manifest.json` 与“关于”页给出许可与对应源码标签链接；Relay 本身的许可不变。
- 额外版本：设置页可导入运行包文件（`.tar.gz`，校验 manifest 与 sha256）。本版不自动下载。

## 4. 固件识别与匹配

- 连接真机时 Relay 已请求 `AUTOPILOT_VERSION`。本版保留并下发：固件类型（HEARTBEAT `autopilot`：3 ArduPilot、12 PX4）、机型（HEARTBEAT `type`，本版只支持四旋翼）、版本（`flight_sw_version` 的主、次、修订与发布类型）、git 哈希（`flight_custom_version` 前 8 字节，如 `fb773567`）、板型（`board_version`，常见板子给出名称，如 Pixracer）。
- 匹配等级（从高到低）：`exact`（同版本且 git 相同）、`version`（同版本）、`series`（同主次版本，取最近修订）、`nearest`（同固件最近的版本，先取较旧者）、`none`（无同固件的包）。
- 界面与 API 给出推荐包、等级和全部候选，可手动选择任意已安装的同固件包；跨固件不可选。`series` 及以下明确提示“控制回路与参数含义可能与真机不同”。
- 机型不是四旋翼 X（如六旋翼、`FRAME_TYPE` 非 X）时，孪生可以生成配置但不能启动，提示原因。

## 5. 孪生配置

`POST /twins/profiles {from_vehicle}` 从一架已连接、已读完参数的真机抓取，保存在数据目录 `twins/<pid>.json`：

```json
{
  "id": "tp-…", "name": "Pixracer 小机", "captured_at": "…", "source": {"vehicle": "…", "label": "…"},
  "firmware": {"family": "ardupilot", "vehicle": "copter", "version": "4.6.3", "git": "…", "board": "Pixracer"},
  "pack": "ardupilot-copter-4.6.3",
  "params": {"ATC_RAT_RLL_P": 0.08, "MOT_THST_HOVER": 0.31, "...": 0},
  "frame": {"preset": "small-250", "mass_kg": 0.42, "wheelbase_m": 0.25, "prop_in": 5.0, "cells": 3, "capacity_mah": 850},
  "home": {"lat": 0, "lon": 0, "alt_m": 0}
}
```

- **参数过滤**（`twin/params.py`，两份清单，带测试）：不进入孪生的是硬件相关项，例如 ArduPilot 的 `SERIAL*`、`*_DEV_ID*`、`INS_*OFFS*`、`INS_*SCAL*`、`COMPASS_OFS*`、`COMPASS_DIA*`、`COMPASS_ODI*`、`COMPASS_MOT*`、`GPS_TYPE*`、`BRD_*`、`CAN_*`、`NTF_*`、`SYSID_THISMAV`、`STAT_*`；PX4 的 `CAL_*`、`SENS_*`、`SYS_AUTOSTART`、`SYS_HITL`、`MAV_*`、`SER_*`、`*_CONFIG`、`UAVCAN_*`、`PWM_*`、`EKF2_*_ID`。其余（控制增益、限幅、失控保护、悬停油门、混控几何、模式与通道映射）全部进入。界面列出“已应用 N 项、未应用 M 项”及原因。
- **机型自适应**：机型预设给出质量、轴距、桨径、转动惯量的初值，操作员可改质量与轴距。电机最大推力由真机学到的悬停油门换算：ArduPilot `MOT_THST_HOVER`（并考虑 `MOT_THST_EXPO`、`MOT_SPIN_MIN/MAX`），PX4 `MPC_THR_HOVER`；使孪生在真机参数下以相同油门悬停。转动惯量由质量与轴距按经验比例估算。
- 配置可改名、编辑机型、删除、导出为 JSON；“从真机重新抓取”更新参数而保留机型。
- 没有真机时，也可以直接选择运行包，以该版本默认参数与 Relay 基线机型启动孪生；基线机型带一套为它调好的起始参数（`defaults/relay-quadx.parm` 与 PX4 对应文件），保证开箱即可稳定悬停。

## 6. 桥接

### 6.1 ArduPilot（JSON）

- 启动：`arducopter --model JSON:127.0.0.1 --speedup 100 -I <n> --defaults <copter.parm>,<relay-quadx.parm>,<profile.parm> --home <lat,lon,alt,hdg>`，工作目录为该孪生的临时目录（参数存储 `eeprom.bin` 每次启动新建，保证与配置一致）。`--speedup` 取大值，由 Relay 的锁步决定实际速度。
- 物理帧：收到 `magic 18458` 的包（`frame_rate`、`frame_count`、`pwm[16]`），按 `1/frame_rate` 推进物理，回一行 JSON：`timestamp`、`imu.gyro`、`imu.accel_body`、`position`（NED，m）、`velocity`（NED，m/s）、`quaternion`、`battery`。`frame_count` 回退表示固件重启，物理随之复位。`SIM_RATE_HZ` 取 1000（不低于主循环 400 Hz × 1.8）。
- 电机：PWM 1000–2000 换算为 0–1 输出，四旋翼 X 电机顺序与 Relay 物理相同（1 右前 CCW、2 左后 CCW、3 左前 CW、4 右后 CW）。
- 传感器由 SITL 依据状态模拟（GPS、气压、磁），IMU 噪声与偏置由 Relay 给出；机体面板的 IMU 噪声、水平误差照常生效。

### 6.2 PX4（MAVLink HIL）

- 启动：`PX4_SIM_MODEL=none_iris px4 -i <n> -d <etc> -w <workdir> -s etc/init.d-posix/rcS`，`RELAY_GCS_PORT` 环境变量由运行包内替换过的 `px4-rc.mavlink` 读取：地面站链路 `mavlink start -x -u 18570+n -o 24550+n`，并删除对 14550、14540 与 13280 的默认外发。Relay 先在 `4560 + n` 监听，PX4 连入。
- 每帧（250 Hz）Relay 发 `HIL_SENSOR`（加速度、角速度、磁、绝对气压、气压高度、温度；`fields_updated` 对应位）并在 10 Hz 发 `HIL_GPS`，等待对应的 `HIL_ACTUATOR_CONTROLS`（`controls[0..3]` 0–1）后推进物理。`time_usec` 为物理时间，PX4 锁步跟随。
- 必须持续发送地面站心跳（Relay 本来就发）；整数参数按字节编码（Relay 已实现）。

### 6.3 生命周期与失败

- 创建：`POST /sims {engine: "sitl", profile?, pack?, frame?, home?}`。进程在 15 s 内未出现心跳则失败（`twin_start_failed`，附进程最后 40 行输出），模拟机不创建。
- 删除或复位模拟机：结束进程并清理临时目录；复位重新启动进程（同配置）。Relay 退出时结束全部固件进程。
- 运行中进程退出：模拟机链路变为丢失，事件 `twin_exited` 附退出码与最后输出。
- 同时运行的孪生数默认最多 8 个（可在设置中改），超出时提示。

## 7. 硬件在环（PX4）

### 7.1 适用范围

- 只支持 PX4：PX4 固件自带 HITL（`SYS_HITL`），无需改固件。ArduPilot 早已移除 HIL，固件不能改的前提下无法做 HITL；界面说明原因并推荐固件孪生。
- 必须经 USB 串口连接（本版新增串口链路，`pyserial`，波特率自动或 921600）。Wi-Fi 数传带不动每秒数百帧的传感器数据。

### 7.2 流程（`POST /vehicles/{id}/hitl {action, confirm}`）

1. 前提：PX4、串口链路、已上锁、操作员附身；输入 `HITL` 确认“已拆下螺旋桨”。
2. 备份：读全部参数，保存到数据目录 `hitl-backups/<vehicle>-<time>.json`。
3. 写入：`SYS_HITL = 1`，`SYS_AUTOSTART` 设为 HIL 四旋翼 X 机架（PX4 1001），其余参数不动；重启飞控（`MAV_CMD_PREFLIGHT_REBOOT_SHUTDOWN`），等待重连。
4. 运行：Relay 以实时 250 Hz 发 `HIL_SENSOR`、10 Hz 发 `HIL_GPS`，读 `HIL_ACTUATOR_CONTROLS` 推进物理；该飞机在 Relay 中显示为“硬件在环”，舞台与遥测照常，电机输出由 PX4 固件锁死。
5. 恢复：`action: stop`（或断开、Relay 退出后下次连接时）把备份中所有被改过的参数写回，重启，重读全部参数并与备份逐项核对；不一致时报告差异（`hitl_restore_mismatch`），并保留备份文件。
- 事件：`hitl_started`、`hitl_restored`、`hitl_failed`。任何一步失败都进入恢复。

## 8. 物理升级

### 8.1 机型（`sim/frame.py::FrameModel`）

质量、轴距、桨径、转动惯量（Ixx、Iyy、Izz）、单电机最大推力、电机升降时间常数、反扭矩系数、阻力系数、电池节数与容量。`physics.Quad(frame=…)` 改用实例参数代替模块常量；缺省机型即现有 120 g 机型，快速模拟的行为与 v0.5.3 一致（回归测试保证）。预设：`micro-120`（现有）、`small-250`（250 mm 级，3S）、`large-450`（450 mm 级，4S）。

### 8.2 传感器（`sim/sensors.py`）

由物理状态生成：IMU（比力与角速度，白噪声与缓慢偏置），气压（国际标准大气，噪声），磁（按位置的偶极近似给出磁偏角与磁倾角，噪声），GPS（10 Hz，位置与速度噪声，卫星数、精度）。快速模拟沿用现有估计路径；孪生与 HITL 使用这些输出。

### 8.3 刚体触地与摔机翻滚

- 接触点：四个机脚（电机下方）、四个桨尖（臂端外缘）、机身顶部。每个穿入地面的点受法向弹簧阻尼力与库仑摩擦力，力作用于接触点，因而产生力矩；取代现在“触地即清零速度、由机脚扶正”的处理。
- 正常降落（低速、近水平）稳稳落地；超过坠毁阈值（沿用竖直 2.5 m/s、水平 3 m/s、倾角 60°）判坠毁、电机停转，但机体继续受力：弹起、翻滚、侧翻或倒扣，停在最终姿态。静止后休眠以节省计算。复位恢复正立。
- 空中被击落或碰撞后的翻滚保持，落地后由接触模型接管。

### 8.4 特技模式（快速模拟）

- `ACRO` 不再等同自稳：摇杆给定机体角速度（ArduPilot `ACRO_RP_RATE` 缺省 360 °/s、`ACRO_Y_RATE` 202.5 °/s；PX4 `MC_ACRO_R_MAX`/`P_MAX` 720 °/s、`Y_MAX` 540 °/s，均读参数），油门直通，无自动回正、无倾角限制，可翻滚、倒飞、侧飞。
- 孪生与 HITL 中的特技模式由真实固件提供。

### 8.5 舞台

- 姿态改用四元数插值（倒飞、翻滚不跳变）；模拟机继续加回水平误差（v0.5.3 修复）。
- 残骸按物理最终姿态显示；孪生与 HITL 的卡片、检查器显示引擎徽标（“固件孪生 ArduCopter 4.6.3 · 精确匹配”、“硬件在环 PX4 1.16.2”）。

## 9. 时间轴

`.ars` v1 的 `mode` 增加 `acro`（ArduPilot ACRO / PX4 ACRO）。旧版 Relay 读到 `acro` 会报字段错误。缺省油门：自稳与特技为 0，定高、定点为 0.5。

## 10. API、事件、错误

| 方法与路径 | 说明 |
|---|---|
| `GET /autopilots` | 已安装运行包（本平台），含来源（内置 / 导入） |
| `POST /autopilots/import`、`DELETE /autopilots/{id}` | 导入运行包文件；只能删除导入的包（操作员） |
| `GET /vehicles/{id}/firmware` | 识别结果与匹配候选（§4） |
| `GET/POST /twins/profiles`、`GET/PUT/DELETE /twins/profiles/{pid}` | 孪生配置（§5）；`POST` 从真机抓取 |
| `POST /sims` | 增加 `engine: "relay" | "sitl"`、`profile`、`pack`、`frame`、`home` |
| `GET /sims/{id}/twin`、`PUT /sims/{id}/frame` | 孪生详情（包、等级、参数应用情况、机型）；上锁时改机型 |
| `GET/POST /vehicles/{id}/hitl` | HITL 状态与 `start`/`stop`（§7） |

- 快照：模拟机 `sim.engine`（`relay` / `sitl` / `hitl`）、`sim.firmware`（固件、版本、包、匹配等级）；真机 `firmware` 扩展为对象并保留旧的字符串字段。
- 事件：`twin_started`、`twin_exited`、`hitl_started`、`hitl_restored`、`hitl_failed`、`autopilot_pack_imported`。
- 错误：`pack_missing`、`pack_unsupported`、`twin_start_failed`、`twin_limit`、`frame_unsupported`、`hitl_unavailable`、`hitl_restore_mismatch`、`serial_unavailable`。

## 11. 界面

- 设置 → 新增“飞控运行包”：列出固件、版本、平台、大小、来源与许可；导入。
- 添加模拟机：引擎二选一（快速模拟 / 固件孪生）；固件孪生下选孪生配置或直接选运行包，机型预设与质量、轴距；推荐项标明来源。
- 真机检查器 → 概览“固件”块：固件、版本、git、板型、匹配等级；“生成孪生配置”“启动孪生”；PX4 串口连接时“硬件在环”按钮，打开分步对话框（确认拆桨 → 备份 → 写入并重启 → 运行 → 恢复与核对），每步显示状态。
- 孪生检查器：引擎徽标、参数应用情况（可展开未应用清单及原因）、机型编辑、“从真机重新抓取参数”。
- 连接真机：增加串口方式（列出可用串口）。
- 时间轴模式下拉增加“特技”。

## 12. Copilot、MCP、SDK

- Copilot 与飞行 MCP：`relay_firmware_identify`、`relay_twin_profile_capture`、`relay_twin_start`（创建孪生模拟机）、`relay_autopilots_list`；HITL 只在应用 MCP 与 Copilot 中提供 `relay_hitl`，必须经批准（不受“全部允许”影响），并要求 `confirm: "HITL"`。
- SDK：`autopilots()`、`firmware(vehicle)`、`capture_twin_profile(vehicle)`、`start_twin(profile=…, pack=…)`、`hitl(vehicle, action)`。

## 13. 验收

- 物理：缺省机型回归（v0.5.3 全部测试通过）；跌落测试（2 m 高倾斜释放会翻滚并停在非正立姿态；0.3 m/s 正常降落保持正立）；特技模式 360° 横滚与倒飞；传感器（静止时比力 −g、气压随高度、磁偏角符号）。
- 孪生：参数过滤清单测试；匹配等级测试；ArduCopter 4.7.2 与 PX4 v1.16.2 孪生经 Relay API 解锁、起飞、定高悬停、降落并上锁（运行包不在时测试跳过；CI 的 Linux 任务下载运行包后执行）；时间轴序列在孪生上执行；进程退出与端口冲突的处理。
- HITL：协议编码与恢复核对用模拟串口测试；真机流程在大机到位后验证（本版文档如实说明）。
- 界面：设置运行包页、添加孪生、真机固件块与 HITL 对话框、四元数姿态的单元测试；双语键集合一致。
- 安装包：各平台运行包数量与体积写入发布说明；macOS 公证通过。

## 14. 已知限制

- 孪生的物理精度取决于机型参数（质量、轴距、推力、惯量）；固件是真的，空气动力与电机是模型。后续可从真机飞行日志估计机型。
- 孪生约以实时运行（裁判可加速）；每个孪生一个进程，建议同时不超过 8 个。
- 孪生连接在本机回环上，不模拟 ESP8266 数传的延迟与丢包。
- Windows 不提供 PX4 孪生；HITL 只支持 PX4 且须 USB。
