# 10 · v0.5.3：时间轴序列（.ars）、模拟机重心与水平误差、解锁前的杆量

日期：2026-11-09（UTC）。基线：v0.5.2（c936bde）。

## 0. 来源

操作员在 v0.5.2 上试飞真机后提出：

1. 已能起飞，但飞机稳定地往前飞，悬停不住；没有外部传感器时陀螺仪每次起飞都有随机偏移，目前靠先用 API 在小油门下把姿态校平。当前的动作序列无法叠加方向与油门，希望有类似摇杆的时序控制：每个时间点都能调节，包括按下去的时长；
2. 做成类似“记录”的时间轴：一行可编辑的操作轴，每次都能微调；支持录制操作队列；设计一种指令序列文件格式与三个字母的后缀，支持导入导出，在真机与模拟机上互相测试；
3. 模拟机的重心“太好”，从不偏移。希望能设定模拟机的重心，让模拟里也能看到起飞后的漂移，在模拟中调好序列后再拿去控制真机；
4. 实验室里的队列没能解锁真实无人机，需要排查。

## 1. 真机不解锁的排查与修复

根因：PX4 与 ArduPilot 在杆量模式（STABILIZE、ALT_HOLD 及 PX4 的 STABILIZED、ALTCTL、POSCTL）下只有在看到飞手输入时才接受解锁：PX4 报 `No manual control input`，ArduPilot 报 `Throttle below failsafe`。实验室部署在飞机上锁时释放杆量（`programs/service.py::_write`），也就是什么都不发；随后的模式切换与解锁命令因此被飞控拒绝。控制面板的解锁能成功，是因为附身后键盘或手柄在持续发杆量。模拟机此前不检查这一条，所以测试与模拟都没有暴露问题。

修复：

- 程序在上锁期间持续发送居中、零油门的杆量（`_idle`），而不是释放；有人在实时打杆时让给人。
- 部署解锁（`arm: true`）先发零油门杆量并等待 `ARM_PRIME_S = 0.6 s`，再切模式、解锁。
- `fleet.arm`：杆量模式下若没有任何新鲜杆量（无技能、无 RC 覆盖、无人打杆），Relay 先发一帧零油门居中杆量（来源 `relay`），等 `ARM_PRIME_S = 0.4 s` 再发解锁命令，并在解锁期间保持杆量新鲜。任何通过 API 解锁的客户端都不再需要自己先推杆。
- 技能（起飞、动作序列、再飞、时间轴）解锁前先发送 0.3 s 的居中杆量（无其他输出时为零油门）再发解锁命令，自稳模式下不再以 0.5 油门请求解锁。
- 飞机已解锁时不预发杆量（零油门在空中即为下降）；等待期间发生急停、控制权变化或预发的杆量被清除时，取消本次解锁，而不是在其后解锁。
- 模拟机按真机行为拒绝：杆量模式下没有飞手输入时解锁失败，PX4 文本 `Arming denied: No manual control input`，ArduPilot 文本 `PreArm: Throttle below failsafe`（`FS_THR_ENABLE = 0` 或 `COM_RC_IN_MODE = 4` 时不检查）。

## 2. 时间轴序列与 `.ars` 文件

### 2.1 文件格式

后缀 `.ars`（ANet Relay Sequence），UTF-8 JSON：

```json
{
  "format": "ars",
  "version": 1,
  "name": "起飞-悬停-降落",
  "mode": "althold",
  "duration_s": 19,
  "trim": { "roll": 0, "pitch": -0.04, "yaw": 0, "throttle": 0 },
  "tracks": {
    "throttle": [
      { "t": 0,   "v": 0.5,  "label": "spool" },
      { "t": 0.5, "v": 0.75, "label": "climb" },
      { "t": 3,   "v": 0.5,  "label": "hover" },
      { "t": 8,   "v": 0.3,  "label": "descend" },
      { "t": 17,  "v": 0,    "label": "settle" }
    ],
    "pitch": [{ "t": 0, "v": 0 }, { "t": 4, "v": -0.08, "ease": "ramp" }, { "t": 6, "v": 0 }]
  },
  "end": "disarm"
}
```

- 四条轨道：`throttle`（0..1）、`pitch`、`roll`、`yaw`（-1..1；右、前、顺时针为正）。
- 每个键开始一个**操作块**，持续到下一个键：`ease: "hold"`（缺省）在块内保持 `v`；`"ramp"` 从 `v` 线性过渡到下一个键的值。第一个键之前保持第一个值，最后一个键之后保持最后一个值；缺少的轨道居中（油门：定高、定点模式为 0.5，自稳为 0）。
- `mode`：可移植的模式名 `stabilize | althold | poshold`，Relay 按飞控映射为 STABILIZE / ALT_HOLD / LOITER 或 STABILIZED / ALTCTL / POSCTL。同一个文件可在真机与模拟机上执行。
- `trim`：叠加到每一帧（roll、pitch、yaw ±0.3，throttle ±0.2），飞行中可改。往前飘就把俯仰调到负值，不改轨道。
- `end`：`disarm`，时间轴结束且确认落地（`landed == ground`）后以零油门上锁；`hold`，保持（定高模式油门 0.5 加微调，自稳模式保持最后的油门）。着陆状态为 `unknown` 时按空中处理，不会在空中把油门拉到零。
- 限制：时长 ≤ 600 s，每条轨道 ≤ 4000 个键，键按时间排序；`source` 为可选的来源说明，原样保留。
- 校验：`relay/sequence.py::normalise`（后端，执行前）与 `web/src/sequence/model.ts::parseArs`（导入时），错误指明字段，例如 `tracks.throttle[1].t`。

### 2.2 执行

内部技能 `sequence`（`skills.py::_tick_sequence`）：切换模式 → 解锁（发送零油门杆量）→ 按时间轴播放 → 结束。`progress_s`、`duration_s`、`phase` 随技能视图下发，界面据此画播放头。

| 方法与路径 | 说明 |
|---|---|
| `POST /vehicles/{id}/sequence` | `{sequence, confirm?, speed 0.25–2, start_at?}`；在地面先解锁，真机须 `confirm: "ARM"`；定点模式需要位置估计；关闭定高辅助的模拟机只接受 `stabilize`。在空中开始时，切换模式期间即发送 `start_at` 处的杆量；自稳序列不能在空中从低于落地油门（0.3）的位置开始。事件 `sequence_started`。 |
| `PATCH /vehicles/{id}/sequence` | `{sequence?, trim?}`：飞行中替换轨道（未播放的操作块立即生效，时间轴位置不变，模式不可改）和/或微调。事件 `sequence_edited`。 |
| `POST /vehicles/{id}/sequence/stop` | 停止时间轴，不切断任何东西：空中（含着陆状态 `unknown`）的定高序列交给悬停技能，自稳序列保持停止时刻的油门与微调；地面直接停止。 |
| `POST /vehicles/{id}/sequence/record` | `{action: start\|stop, name?}`：记录飞机解锁期间实际收到的杆量（人、序列、程序均可），20 Hz；`stop` 返回 `.ars` 文档（Ramer–Douglas–Peucker 简化，容差 0.015，最长 2 s 一个键）。事件 `sequence_recording`。 |
| `GET /history/sessions/{sid}/sequence` | 记录中从解锁到上锁的杆量，转换为 `.ars` 文档。 |

附身规则不变：操作员须附身；超过接管阈值的打杆接管并停止时间轴。`sticks` 飞行等级下的会话只能以 `stabilize` 执行。

### 2.3 界面：时间轴面板

- 入口：控制 → 时间轴序列 → 打开时间轴；命令面板“打开时间轴”；记录 → 作为序列打开。面板停靠在舞台下方，高度可拖动，打开状态按观看者记忆。
- 摇杆条：时间轴最上方一行，在每个杆量变化时刻画出左右两个小摇杆的位置（A 时刻两杆在哪、B 时刻变到哪），点击跳到该时刻。
- 光标处摇杆：侧栏顶部两个摇杆面板，显示光标（飞行中为播放头）处两个摇杆的位置；拖动摇杆即写入从该时刻起的杆量，光标落在操作块中间时自动切分，只写入被拖动的轴；按住 Shift 精调。左右手布局跟随“设置 → 控制器”的摇杆模式（模式 2 左手油门，模式 1 右手油门）。
- 轨道：油门、俯仰、横滚、偏航四行，每行由连续的操作块组成，块高表示杆量、块宽表示时长，块内显示名称、杆量与时长（按块宽截断）。方向轨道按最大杆量自动缩放到 ±0.1 / ±0.25 / ±0.5 / ±1，刻度标在轨道名旁，小杆量也看得清、拖得细。
- 编辑：
  - 上下拖动块改杆量（按住 Shift 精调 ×0.2）；拖右边缘改时长，后面的块随之移动；拖左边缘移动起点，其他块不动；双击在指针处切分。
  - 选中后：↑/↓ 杆量 ±0.01（Shift ±0.05）；←/→ 时长 ±0.1 s（Shift ±0.5 s）；S 在光标处切分；Delete 删除；⌘/Ctrl+Z 撤销，Shift 加同一组合键重做。
  - 块参数面板：名称、杆量滑块与数值、持续时间、保持或渐变、切分、在后面插入、删除。
- 全局微调：俯仰、横滚、偏航、油门四个滑块，飞行中松手即发送。
- 执行栏：执行序列、从光标处执行、停止序列、录制（红色按钮与计时）、状态（切换模式、解锁、执行中 t / 总时长、保持中）、当前杆量与高度。真机在地面执行时弹出 ARM 确认。
- 起飞模板：离地 → 爬升 → 悬停 → 下降 → 落地，每块带名称。导入、导出 `.ars`；文档按观看者保存在本机。
- 面板内的按键归面板（`data-own-keys`），飞行与外壳快捷键让位；手柄飞行不受影响。Esc 例外：先取消选中操作块，未选中时仍停止飞机。撤销、重做与其他编辑一样会发给正在执行该序列的飞机。

## 3. 模拟机重心与水平误差

- 机体新增 `with_assist`（布尔，缺省关）：开启后，重心偏移、水平误差、电机效率、桨叶损伤、IMU 噪声与起飞重量在悬停辅助开启时同样生效。定高保持高度，机身仍像真机一样倾斜和漂移。电压、地效与紊流仍只在悬停辅助关闭时生效。
- 新增 `arm_bias_deg`（0–3°）：每次解锁在横滚、俯仰上各抽取一个 ±`arm_bias_deg` 的随机水平误差，叠加到 `level_trim_deg`，对应“陀螺仪每次起飞随机偏移”。由种子与解锁次数决定，可复现。
- `GET /sims/{id}/airframe` 增加 `level_now_deg`（本次飞行的水平误差），`active` 改为“悬停辅助关闭或 `with_assist`”。快照仍只含预设与种子。
- 界面：概览 → 机体增加“定高下同样生效”开关、“每次解锁的随机水平误差”滑块，以及生效时显示的“本次飞行水平误差”。
- 推荐流程：在模拟机上设定水平误差或重心偏移并开启 `with_assist`，执行时间轴，观察漂移方向，用微调抵消，再把同一个 `.ars` 拿到真机执行。验收数据：2° 横滚误差在定高悬停 6 s 内漂移 > 2 m；横滚微调 −2/30 后漂移降到不足三成，方向相反则加倍。

## 4. Copilot 与智能体

- Copilot：`relay_timeline_run`（等待结束并逐秒报告进度）、`relay_timeline_edit`、`relay_timeline_stop`、`relay_timeline_record`、`relay_timeline_from_record`；前两个属于运动工具，真机须批准（或“全部允许”）。`airframe_set` 接受 `with_assist` 与 `arm_bias_deg`。系统提示写入时间轴调参流程。
- 飞行 MCP：同名五个工具（共 26 个；`sticks` 等级 18 个，序列只能以 `stabilize` 执行）。
- SDK：`timeline_run`、`timeline_edit`、`timeline_stop`、`timeline_record`、`timeline_from_record`、`wait_timeline`，以及 `load_ars`、`save_ars`。
