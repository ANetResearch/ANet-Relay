# ANet Relay 产品定义（设计 v1.0，2026-11-06）

> 本文是 ANet Relay 设计三件套的第一份：01 产品定义（为什么、给谁、做什么、做到什么程度）→ 02 体验设计（长什么样、怎么用）→ 03 系统设计（怎么实现、接口与安全）。三份文档一起构成实现的唯一依据；需求编号 `R-xx` 在 02、03 与测试中引用。
> 输入：产品负责人的全部原话（`refs/user-requirements.md`）、旧 demo `anet4d-gcs`、《小型无人机平台使用资料》、ANet4D 主仓库的设计体系与研究笔记（d06 渐进暴露、ADR-227 技能词表与指挥网关）。

## 1. 定位

**ANet Relay — Ground control for agent swarms.**
中文释义：面向智能体机群的地面端。

ANet Relay 对标 QGroundControl：它是一个桌面地面端，在同一 Wi-Fi 局域网里发现、连接、监视和控制一群小型无人机。它与 QGC 的区别，正是它存在的理由：

1. **机群优先**：QGC 以"一架飞机"为中心组织界面；Relay 以"整个机群、谁在控制哪一架"为中心组织界面。
2. **附身**（Possession）：人可以拿起手柄（DualSense）或键盘，随时接管机群里的任意一架做精细控制；多个手柄可以同时各控一架。
3. **接力**（Relay）：人松手后，这一架自动交还给原来认领它的智能体，智能体继续它的任务。人与 AI 之间的控制权交接是可见的、有记录的、规则确定的。
4. **智能体接口**：本机 API（REST、WebSocket、MCP、Python SDK）让外部 LLM / agent harness（DeepSeek agent、Claude、自研 harness）查询状态与拓扑、认领飞机、下达从杆量到技能（起飞、悬停、前往、降落）的各级指令。Relay 本身不内置智能。
5. **练习与评测**：模拟机与真机走同一条接口；虚拟穿环航线让人练手、让智能体打榜，真机在具备位置估计时也能穿同一串虚拟环。

名字来自第 3 点。产品名在中英文界面中都写作 **ANet Relay**，不翻译；它是 ANet 家族（ANet、ANet4D）的一员，视觉系统与 ANet4D 完全一致。

## 2. 质量标杆

负责人的原话是"非常有 B 格、极简、有启动动画、优秀布局"，"DJI 他们的就很帅，启动的时候有那种质感，高级"。据此确定四条质量标杆，任何设计取舍都以它们为准：

| 标杆 | 含义 | 反例（旧 demo） |
|---|---|---|
| Q1 克制 | 一屏只说一件最重要的事；颜色、动效、文字都稀缺地使用；红色只表示"已解锁"或"危险" | 六个标签页平铺、到处是数字 |
| Q2 质感 | 启动、接入手柄、穿环这些"时刻"有精心编排的动效与排版，像 DJI 设备接入那样有仪式感但不炫 | 一片黑、黑边图标 |
| Q3 确定 | 任何时刻一眼看出：哪几架在飞、谁在控制哪一架、哪一架需要我；危险操作永远有确认，急停永远可达 | 附身状态藏在标签页里 |
| Q4 诚实 | 拿不到的数据显示"—"并说明原因；做不到的事（例如真机没有位置估计时穿环）明确告诉用户，不猜、不演 | 模拟机只在渲染进程里"演" |

## 3. 用户与场景

### 3.1 用户

| 用户 | 典型任务 | 关心什么 |
|---|---|---|
| U1 操作员（负责人本人、实验室成员） | 在围网场地里连上 1–6 架小机，做起飞前检查，手柄飞、看智能体飞、必要时接管 | 安全、确定、手感、颜值（要给人看） |
| U2 智能体开发者 | 写 harness，让 LLM 经 API 控制单机 / 多机；先在模拟机上跑通再上真机 | 接口直接、文档清楚、模拟与真机一致、可复现 |
| U3 观众 / 评审 | 看演示 | 第一眼的质感、看得懂人机接力 |

### 3.2 关键场景

| # | 场景 | 结果 |
|---|---|---|
| S1 | 新机开箱：数传处于 AP 模式（热点 `anet4d-a01`，`192.168.4.1`），操作员连上热点，Relay 识别出"这是一块未配网的数传"，一步把它切到 Station 模式加入局域网 `anet4d`；操作员切回局域网，飞机出现在机群里 | 3 分钟内完成，无需打开数传网页 |
| S2 | 首飞：无桨确认心跳、固件、通道方向（标定）、电机转向（电机测试）、电压；装桨；手柄附身、输入 ARM 解锁、起飞悬停、降落 | 起飞前检查逐项通过才允许解锁 |
| S3 | 多机监视：局域网里 4 架真机 + 2 架模拟机，操作员一眼看到每架的链路、电池、模式、控制者 | 信息密度高但不乱 |
| S4 | 人机接力：harness 认领 3 架执行任务；其中一架出状况，操作员按住手柄 Options 附身它；处理完松手，这架回到 harness，harness 收到 `relay_handback` 事件后继续 | 交接时间线可见、可回放 |
| S5 | 练习：插上 DualSense → 有质感的接入提示 → 一键"穿环练习"（自动加一架模拟机、加载航线）→ 追尾视角飞完 4 个环，看到分段与总时间 | 1 分钟内从插上手柄到起飞 |
| S6 | 真机穿环：有位置估计的真机被附身后，开始同一条航线，虚拟环叠加在三维舞台上，过环判定与计时同模拟机 | 没有位置估计时诚实说明不可用 |
| S7 | 智能体开发：不接任何硬件，用 SDK 或 MCP 在模拟机上让智能体起飞、前往、穿环、降落 | 同一段代码换到真机只改 id |
| S8 | 复盘：打开飞行记录，看一次飞行的电压、高度、姿态曲线、事件、控制权时间线、穿环成绩 | 能回答"那一刻谁在控制、做了什么" |
| S9 | 告警：心跳丢失、低电压、坠毁、14550 端口被 QGC 占用 | 告警分级、可追溯、急停可达 |

## 4. 需求

级别：**M** 必须（v0.1 发布条件）、**S** 应该（v0.1 尽力，未完成须列入发布说明）、**C** 以后。

### 4.1 接入

| ID | 级别 | 需求 | 验收 |
|---|---|---|---|
| R-01 | M | 单个 UDP 14550 端口服务全部真机，按来源 IP 区分；GCS 心跳 1 Hz | 两架假飞机（PX4、ArduPilot）同时在线、互不串扰 |
| R-02 | M | 局域网扫描：探测本机所在网段（≤ /22）TCP 80 上的 MAVLink 数传页，并向子网广播 GCS 心跳唤醒；进度可见 | 假数传被扫到；/24 网段扫描 ≤ 8 s |
| R-03 | M | 按 IPv4 直连（可指定端口） | 输入地址后 3 s 内出现 |
| R-04 | M | 数传配网向导：识别 mavesp8266 数传（含处于 AP 模式时），读取其参数，一键写入 Station 模式、SSID、密码、DHCP、端口并重启 | 对假数传完成全过程；对未知固件退化为"在应用内打开数传设置页" |
| R-05 | M | 14550 被其他地面站占用时，明确提示并可重试 | 端口被占时有常驻告警与"重试" |
| R-06 | S | 记住每架机的名字（按 IP）与最近连接过的地址 | 重启后名字仍在 |

## 5. 不做（v0.1）

- 内置 LLM、任务规划、群体算法（这些在外部 harness 里）。
- 航点任务编辑、地图底图、固件刷写（用 QGC / Mission Planner）。
- 多个智能体同时写同一架飞机。
- 远程（非本机）访问 API。
- 视频流转发给智能体（智能体拿不到图传；C 级）。

## 7. 名词

| 名词 | 英文 | 含义 |

| 机群 | Fleet | 当前 Relay 看到的全部飞机（真机 + 模拟机） |
